# ポートフォリオ意思決定ワークスペース 実装計画

最終更新: 2026-08-15

状態: **計画レビュー中。現行 `/premium/portfolio` はPhase 0の読み取り版であり、完成品ではない。**

## 1. 正本と対象範囲

クロスリポジトリ全体の目的、ChatGPT運用、API、完成条件は、stock-notesの
[ポートフォリオ意思決定プラットフォーム正本計画](https://github.com/Yuichi-TanakaJP/stock-notes/blob/main/docs/portfolio-platform-plan.md)
を正とする。

この文書は、正本をMiniToolsの画面、データ取得、銘柄ダッシュボード連携、UATへ落とす実行計画である。

## 2. MiniToolsの役割

MiniToolsはポートフォリオ方針の主入力画面ではない。主入力はChatGPTとの会話であり、MiniToolsは
保存された判断を継続利用するための意思決定ワークスペースである。

ユーザーが画面を開いたとき、最初に答えられるべき質問は次のとおり。

- 今のポートフォリオの強みと弱みは何か
- 追加資金をどこへ、いくら、どの条件で入れるのか
- 今すぐ買わない銘柄は、なぜ待つのか
- どの銘柄の分析が古く、何を再確認すべきか
- 前回の方針から何が変わったか
- 次に実行・監視するアクションは何か

保有数量や損益の表は必要だが、上記判断を支える補助情報として扱う。

## 3. 現状とギャップ

### 現在実装済み

- `/premium/portfolio` のPremium認証
- Supabase Auth/RLSによる本人データの読み取り
- 最新ready snapshotの評価額・取得額・損益表示
- 口座別position、snapshot履歴の表示
- 保存済みreview/itemの読み取り表示

### 未実装

- ChatGPT相談開始・継続導線
- portfolio context APIを使った判断材料の集約
- 全体診断、弱み、不足する役割
- 新規資金配分、待機資金、見送り理由
- 分析鮮度、決算後未分析、取得失敗の表示
- portfolio action
- reviewとsnapshotの鮮度差
- 前回reviewとの差分
- 銘柄ダッシュボードとの双方向連携

現行画面を「表の見栄えを改善する」だけでは、目標は達成しない。

## 4. 標準ユーザーフロー

### 4.1 最初の棚卸し

1. 証券会社CSVがstock-notesへ取込済み
2. ユーザーがMiniToolsを開く
3. review未作成を検知し、保有件数・基準日と「ChatGPTで棚卸しを始める」を表示
4. ユーザーがカスタムGPTで相談する
5. GPTがcontextを読み、全体方針と銘柄別判断を提示
6. ユーザー確認後、GPTがreviewを保存・確定
7. MiniTools再読込で意思決定画面へ反映

### 4.2 追加資金の相談

1. 「100万円を追加したい」等をChatGPTへ伝える
2. GPTが最新snapshot、最新分析、前回reviewを取得
3. 資金配分、待機資金、条件、理由を提示
4. 修正後にreviewを保存
5. MiniToolsで配分合計と優先順位を確認

### 4.3 再評価

1. 新しいCSV、決算、分析、条件成立のいずれかが発生
2. MiniToolsに「要再レビュー」と対象理由を表示
3. ChatGPTで再相談
4. 新reviewを保存
5. 前回との差分をMiniToolsで確認

## 5. 情報設計

主ナビゲーションは次の3画面とする。

1. **意思決定**: 全体方針、投入計画、診断、アクション
2. **保有一覧**: 商品別集約、口座別明細、取得・評価情報
3. **履歴**: snapshot、review、前回との差分

現在の「表示・記録・方針」はデータ分類であり、ユーザーの目的を表していないため廃止する。

## 6. 意思決定画面

### 6.1 ヘッダー

- ポートフォリオ名
- snapshot基準日・取込日時
- review基準日・状態
- `最新`、`要再レビュー`、`分析不足`等の状態
- ChatGPTで相談を開始・継続するボタン

状態判定例:

| 条件 | 表示 |
|---|---|
| reviewなし | 最初の棚卸しが必要 |
| snapshot.as_of > review.as_of | 保有状況更新後、未レビュー |
| 決算日 > source analysis.as_of | 決算後未分析 |
| 未分析instrumentあり | 分析不足N件 |
| context取得失敗 | データ取得失敗。空ポートフォリオとは区別 |

### 6.2 全体判断

- 今回の結論
- ポートフォリオの強み
- 弱み・集中リスク
- 不足する役割
- 今回の大方針
- 判断に使ったデータ基準日

文章を一段落で埋めず、「結論」「理由」「リスク」「次回確認」に分ける。

### 6.3 新規資金の投入計画

優先順位順に次を表示する。

| 項目 | 内容 |
|---|---|
| 順位 | 新規資金の優先順位 |
| 商品 | コード、名称、現在構成比 |
| 提案 | 投入金額、投入後比率 |
| 判断 | 買い増し、押し目待ち、維持、縮小等 |
| 条件 | 価格、利回り、PER、決算等 |
| 理由 | portfolio上で今増やす理由 |
| 待つ理由 | 条件未成立、分析不足、集中等 |
| 鮮度 | 最終分析、次回/前回決算 |

画面上部に必ず次を表示する。

- 想定新規資金
- 提案配分合計
- 待機資金
- 配分未確定額

### 6.4 ポートフォリオ診断

- 役割別構成
- 資産種別・口座別構成
- 上位銘柄集中
- 役割の不足・重複
- 未分析・分析期限切れ・条件未設定の件数

グラフは判断を補助する場合だけ使用し、グラフ自体を成果にしない。

### 6.5 アクション

- 対象
- やること
- 期限または条件
- 状態
- 発生元review
- 完了後の結果分析

## 7. 保有一覧

### 7.1 商品別集約

- コード・名称・資産種別
- 合計数量、平均取得単価、現在値
- 取得額、評価額、損益、構成比
- 保有口座
- role、stance、need、priority
- 買い増し条件、次回アクション
- 分析鮮度

国内株は銘柄ダッシュボードへdeep linkする。投資信託は個別株分析へ強制リンクしない。

### 7.2 口座別明細

監査・確認用の副表示とする。NISAと課税口座の同一銘柄を失わない。

## 8. 履歴画面

- snapshotの基準日、取込日時、position件数
- reviewの基準日、状態、対象snapshot
- 前回からの順位、配分、stance、needの変更
- 追加・削除・数量変化したposition
- 変更理由、参照analysis/thesis

## 9. 銘柄ダッシュボード連携

### Portfolio → Stock Notes

- 国内株行から該当銘柄を展開した状態で開く
- 未分析・決算後未分析なら理由を引き継ぐ
- 分析用プロンプトまたはChatGPT相談導線を表示する

### Stock Notes → Portfolio

銘柄詳細へ以下を追加する。

- 保有数量、平均取得単価、評価額、構成比
- 最新portfolio reviewのrole、stance、need、priority
- 買い増し条件、提案金額、変更理由
- portfolio基準日、reviewへのリンク

個別thesisの強気・弱気と、portfolio上の追加優先度は別のラベルとして表示する。

## 10. データ取得方針

MiniToolsはSupabase Auth/RLSを使って本人データを読む。表示用の単純な読み取りは直接取得できるが、
判断文脈の定義はstock-notes `GET /portfolio/context` と一致させる。

同じ集計・鮮度判定をMiniToolsとstock-notesで別実装して不一致にしない。次のいずれかで共有する。

1. stock-notes contextをMiniToolsサーバー経由で取得する
2. DB view/RPC等で正規化した共通読み取り契約を作る

採用方式はcontext API PRで、認証、応答時間、キャッシュ、障害分離を比較して決定する。

## 12. UAT計画

実装完了はサンプル表示ではなく、実データで次を確認する。

- 49position、39instrument、5口座が欠落なく表示される
- INPEX 1605が96株、取得単価1,927円として表示される
- ChatGPTで保存したreviewが手入力なしで反映される
- 100万円の提案配分合計と待機資金が一致する
- INPEXの個別評価と追加優先度が別表示される
- reviewより新しいsnapshotで要再レビューになる
- 未分析、決算後未分析、API失敗を空状態と誤認しない
- portfolioと銘柄ダッシュボードを往復できる
- 前回reviewとの差分を確認できる

実装PRごとに [`docs/uat/portfolio.md`](../uat/portfolio.md) を更新し、実施証跡はPR本文へ残す。

## 13. 完成条件

MiniTools側は、次が成立したときだけ完成とする。

> ChatGPTで保存したポートフォリオ判断を、手入力なしで読み取り、次に投じる資金、待つ条件、
> 不足する分析、実行すべきアクション、前回との差分を確認でき、個別銘柄分析へ往復できる。
