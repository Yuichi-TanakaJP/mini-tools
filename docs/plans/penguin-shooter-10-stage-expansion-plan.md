# ペンギンシューター 10大ステージ・武器拡張実装計画

## 結論

ペンギンシューターを、10大ステージ・合計100小ステージの構成へ再編し、ステージ進行に合わせて複数武器を解放する。既存の5大ステージ・100小ステージの遊技量は維持し、1大ステージあたりの小ステージを20から10へ変更する。

実装は次の順番で行う。

1. この計画書とUI設計書を先にコミットする
2. ステージデータと武器データの契約を拡張する
3. 武器切替、弾の挙動、HUDを実装する
4. ステージボスSVGをゲーム画面へ組み込む
5. 10ステージの背景・ボス・難易度を接続する
6. UAT、lint、テスト、build、Previewで確認する

## 前提とスコープ

### 今回の前提

- 「ステージを10まで」は10大ステージと解釈する。
- 合計小ステージ数は、現在の100を維持する。
- 各大ステージは10小ステージとする。
- 小ステージ5を中間ボス、小ステージ10をステージボスとする。
- Stage 10のステージボスは、既存の機械系から外れた生物的な次元裂け目デザインとする。
- 2人プレイと永続進捗保存は、既存の凍結方針を維持する。

### 含めるもの

- 大ステージ10個のデータ定義
- 10大ステージの背景テーマ・アクセント・BGM基準値
- ステージボス10体のSVG接続
- Standard、3-Way、Rainbow Laser、Snack Missile、Fridge Beam、Lucky Coin Cannon
- 既存ボムとの武器UI統合
- PC・スマホの武器切替UI
- ステージ、武器、ボス状態を同時に確認できるHUD

### 含めないもの

- 2人プレイの操作実装
- セーブ、ランキング、オンライン同期
- 外部音声ファイルの導入
- ボスSVGを自動生成する仕組み
- 10体の中間ボス専用イラスト（初回はステージボスSVGの簡略表現を検討）

## 10大ステージ案

| Stage | テーマ | 役割 | ステージボス |
|---:|---|---|---|
| 1 | はじまりの町 | 操作チュートリアル | スクラップ要塞 |
| 2 | 緑の王国 | 拡散弾の導入 | 緑の王国城塞 |
| 3 | 氷海 | 減速・回避 | 氷海クラーケン |
| 4 | 砂漠遺跡 | 貫通レーザー導入 | 砂漠スフィンクス |
| 5 | 雲上都市 | 中盤の速度上昇 | 雲上都市戦艦 |
| 6 | 月面 | 追尾ミサイル導入 | 月面コアゴーレム |
| 7 | 火星 | バースト攻撃強化 | 火星火山要塞 |
| 8 | 機械惑星 | コイン武器導入 | クロックワーク皇帝 |
| 9 | ブラックホール | 高密度弾幕 | ブラックホール・イーター |
| 10 | 異次元 | 最終決戦・Shoot救出 | ワールドリフト |

各ステージの小ステージは01〜10とし、05に中間ボス、10にステージボスを配置する。全体番号は01〜100を維持する。

## 武器仕様

武器は数値レベルではなく `WeaponId` を現在選択状態として管理する。武器定義はデータ側に置き、発射関数は定義を解釈する。

| ID | 解放 | 挙動 | 代償 / 制限 |
|---|---|---|---|
| `standard` | 初期 | 高速の直線弾1発 | なし |
| `spread-3` | Stage 2 | 左右へ広がる3発 | 1発あたりの威力は標準 |
| `rainbow-laser` | Stage 4 | 高威力の光線 | 発射間隔が長い |
| `snack-missile` | Stage 6 | 近い敵を追尾するミサイル | 弾速が遅い |
| `fridge-beam` | Stage 7 | 敵を一定時間減速 | ダメージが低い |
| `coin-cannon` | Stage 8 | 高威力の直線弾 | 発射時にコイン1枚消費 |
| `panic-bomb` | 初期1個 | 画面内の敵・障害物を一掃 | 使い切り |

武器解放は自動で行い、解放済み武器はHUDまたはスマホ操作パネルから切り替える。現在の3-Way自動強化は `spread-3` の解放処理へ移行する。

## ボスSVG接続方針

- `public/games/penguin-shooter/bosses/` の10体をステージボスへ割り当てる。
- `BossDefinition` に `asset` または `assetPath` を追加する。
- `EnemyView` はステージボスの場合にSVGを表示し、HPバー、名前、攻撃ラベルはDOMで重ねる。
- SVGは表示と発光の責務だけを持つ。
- 当たり判定、弾の発射位置、HP、攻撃パターンは `ToolClient.tsx` とステージデータで管理する。
- Stage 10は機械系ボスのCSS部品を再利用せず、SVGの異質な輪郭をそのまま見せる。

## 実装フェーズと受入条件

### Phase 0: 設計

- 計画書とUI設計書が `docs/plans/` に存在する
- `docs/plans/index.md` から参照できる
- 10×10構成、武器ID、武器切替操作、ボス表示ルールが記録されている

### Phase 1: データ契約

- 10大ステージが型安全に定義される
- 全体小ステージ番号が01〜100になる
- 各ステージに中間ボス・ステージボスが存在する
- `CLEAR_TARGET`、`FINAL_STAGE`、ステージ遷移がデータから計算される

### Phase 2: 武器とUI

- 解放済み武器をPCキーで切り替えられる
- スマホ画面で現在武器と切替ボタンが確認できる
- コイン消費武器は残高不足時に発射されない
- 武器ごとに弾道または効果が視覚的に異なる

### Phase 3: ボスと演出

- Stage 1〜10のステージボスが個別SVGで表示される
- HP、名前、攻撃ラベルがボス本体と重ならない
- Stage 10ボスが他の9体と異なるデザイン系統で表示される

### Phase 4: 検証

- `npm run lint`
- `npm test`
- `npm run build`
- Desktop 1280x720 / 1024x768
- Mobile 390x844 / 430x932 / 573x997
- 画面読み上げ用の武器名、ボス名、残弾・コイン状態を確認

## リスクと緩和策

| リスク | 緩和策 |
|---|---|
| 10ステージ化でゲームループが複雑になる | 進行値とステージ設定を `stageData.ts` に集約する |
| 武器追加で衝突処理が分岐しすぎる | 弾に共通の `damage` / `pierce` / `effect` 契約を持たせる |
| SVGとDOMの重なりでHP表示が読めない | ボス表示領域と情報ラベル領域を分けたUI設計にする |
| モバイルHUDが詰まる | 武器パネルを横スクロールまたは2行グリッドにする |
| 難易度が急上昇する | ステージごとに敵速度、発射間隔、解放武器を別々に調整する |
