# ペンギンシューター UI設計（10ステージ・武器拡張版）

## 目的

ゲーム中に「いま何ステージか」「次に何を目指すか」「どの武器を使っているか」「ボスがどれだけ残っているか」を、プレイを止めずに把握できるUIを設計する。

本書は実装前のUI設計であり、コンポーネント・CSS・配置の判断基準とする。

## 2026-08-15 ゲームモード・大画面・スティック操作（v3）

ボスが画面端から再登場するとHPが全回復し、長期戦で進行不能になる問題と、ゲーム盤面が小さく移動ボタンを見ながら操作する問題を受け、以下をv3の基準とする。

- ボスは画面外へ退避して再登場しても、同じステージ・同じチェックポイントの残HPを保持する。撃破時だけ保持値を消去する。
- ゲームモードは1〜5から開始前に選択する。Mode 1は敵数・敵HP・ボスHPを最小、Mode 5は最大とし、選択中のモードをHUDへ常時表示する。
- デスクトップでは盤面の高さ上限を引き上げ、ゲームカードを主役にする。盤面外の武器・モード・補助情報は整理して、盤面を横幅いっぱいに使う。
- スマホの移動UIは4方向ボタンを廃止し、ペンギンエイリアンシューターと同じ、押した位置からノブをスライドさせるアナログスティックにする。指を離すと即時停止する。
- スティックは44px以上のタッチ領域を確保し、射撃・ボムは右側の独立ボタンとして維持する。

### ゲームモード基準

| Mode | 敵の出現密度 | 通常敵HP | ボスHP倍率 | ねらい |
|---:|---|---:|---:|---|
| 1 | 少ない | 1 | 0.65 | 初心者・短時間プレイ |
| 2 | やや少ない | 1 | 0.80 | 標準より軽め |
| 3 | 標準 | 2 | 1.00 | 現行バランス |
| 4 | 多い | 2 | 1.20 | 高密度戦闘 |
| 5 | 最大 | 3 | 1.45 | 高難度チャレンジ |

ボスHPの再登場時繰り越しを第一の解決策とし、モード倍率で入口の難易度を調整する。Mode 1でもHPを0未満にせず、少なくとも1を保証する。

## 2026-08-15 モバイル実機フィードバック反映（v2）

添付されたスマホ画面で、ゲーム盤面の下端と固定ナビゲーションが近く、操作パネルの一部が画面下に隠れる状態を確認した。また、ボス帯とボス本体の縦方向の予約領域が重なり、SVGの絵柄がHP表示に隠れることがあった。以下をv2の基準とする。

- モバイルの盤面スケールは幅だけで決めず、画面高の54%を上限（最大500px）にして、操作パネルを同じ画面のスクロール範囲へ収める。
- 固定ナビゲーションと重ならないよう、モバイルページ下部に128pxの安全余白を確保する。
- 盤面上部は「HUD → Life帯 → ボス帯」の順に予約し、ステージボス本体はボス帯の下（論理座標y=180付近）から表示する。ボス本体へ名前・HPを重ねない。
- Lifeは横長HUDから分離し、`LIFE 10/10` と残数ピップを盤面左上へ常時表示する。3以下では危険色に切り替える。バリアの発動秒数・クールタイムも同じステータス行に残す。
- ボス帯は名前、攻撃名、HP数値、HPバーを1つの帯にまとめ、ボス絵柄と交差しない高さを持つ。

### ボスHPの難易度基準（v2）

すぐに撃破される問題を避けるため、ボスHPを段階的に引き上げる。中間ボスは30〜150、ステージボスは80〜600の範囲とし、ステージ番号に対して単調増加させる。武器の解放による火力上昇は維持しつつ、ステージボス戦が短時間で終わらないことを優先する。

## 情報設計

ゲーム中の情報を3つのグループに分ける。

1. **Progress**: Stage、Small、救出進捗、ステージ名
2. **Combat**: Weapon、武器切替、ボム、ライフ、バリア
3. **Feedback**: スコア、コイン、コンボ、ボス名、HP、攻撃名

重要度は、ゲームプレイに直結するCombatを最上位、次にProgress、補助情報としてFeedbackとする。

## デスクトップ構成

```text
┌──────────────────────────────────────────────┐
│ Stage 03 氷海 / Small 04     Score   🪙 12   │  ← Progress + Feedback
│ Rescue 24/100                 ❤️ 10  🛡️ 3s   │
├──────────────────────────────────────────────┤
│                                              │
│                 GAME BOARD                   │
│            敵・弾・ボス・プレイヤー           │
│                                              │
│       ┌──────── BOSS INFO ────────┐          │
│       │ 氷海クラーケン  HP 62%     │          │
│       │ 低重力ホバー / クロー       │          │
│       └───────────────────────────┘          │
├──────────────────────────────────────────────┤
│ Weapon: [1 Standard] [2 3-Way] [3 Laser]     │
│ [4 Missile] [5 Beam] [6 Cannon]   [BOMB]     │  ← Combat
├──────────────────────────────────────────────┤
│ ◉ スティック移動 / Space 発射 / B ボム          │
└──────────────────────────────────────────────┘
```

- ゲーム盤面は既存の720×820論理座標を維持し、デスクトップでは画面高に合わせて最大1.12倍まで拡大する。
- ボス情報は盤面上部の専用帯へ置き、ボス本体の上へ直接ラベルを重ねない。
- 武器パネルは盤面の外側に置き、ゲーム領域を狭めない。
- ScoreとCoinは右上にまとめ、LifeとBarrierはその下にまとめる。

## モバイル構成

```text
┌─────────────────────┐
│ S03 氷海   🪙12 ❤️10 │
│ Small 04  Rescue 24% │
├─────────────────────┤
│       GAME BOARD     │
│   ┌───────────────┐  │
│   │ BOSS HP 62%   │  │
│   └───────────────┘  │
├─────────────────────┤
│ Weapon 3-Way  [切替] │
│ [Laser][Missile][Beam]│
│ [ ◉ スティック ] [SHOT]│
│                  [BOMB]│
└─────────────────────┘
```

- 画面幅390pxでは武器ボタンを横スクロール可能な1行にする。
- 画面幅430px以上では武器ボタンを2行にして全種類を表示する。
- スティックは左側、ShotとBombは右側に固定し、誤タップ防止のためBombはShotより小さくしない。
- 武器切替はタップ後もゲームを一時停止しないが、選択状態を明るい枠で表示する。
- 重要な状態は絵文字だけに依存せず、`Weapon: Laser`、`Bomb 1` のようなテキストも併記する。

## 状態別UI

| 状態 | 主表示 | 操作 |
|---|---|---|
| idle | タイトル、開始、操作説明 | 開始 |
| opening | 5カット演出、スキップ | スキップ |
| playing | 通常HUD、武器パネル、ゲーム盤面 | 移動・発射・切替・ボム |
| boss | ボス帯、HP、攻撃名、危険演出 | 通常操作＋武器切替 |
| cleared | Shoot救出、スコア、10ステージ達成 | リトライ |
| gameover | スコア、到達ステージ、リトライ | リトライ |

## 武器UI仕様

- 現在武器には `aria-pressed="true"` を付ける。
- 未解放武器はロック表示と解放Stageを表示する。
- コイン消費武器は `🪙 1` のコストをボタン内に表示する。
- 現在武器名をゲーム盤面外のHUDにも表示する。
- PCは数字キー `1`〜`6` で切替する。
- PCの `Space` は発射、`B` はボムを維持する。
- スマホは武器ボタン、スティック、SHOT、BOMBを独立したタッチターゲットにする。

## ボスUI仕様

- ボス出現時、盤面上部にボス帯を表示する。
- ボス帯には名前、攻撃ラベル、武器ラベル、HPバーを表示する。
- HPバーは色だけでなく、`HP 62%` のテキストを併記する。
- Stage 10は「FINAL BOSS」バッジを追加する。
- ボスSVGは帯の下に配置し、名前・HPをSVG上に埋め込まない。
- 警告レーザーやスイープ攻撃は、HUDと混同しないよう盤面内だけで発光させる。

## レスポンシブ基準

| 幅 | 方針 |
|---:|---|
| 768px以上 | デスクトップ構成。武器パネルは横一列 |
| 573〜767px | 盤面を縮小。武器パネルは2行 |
| 430〜572px | HUDを2行化。武器パネルは2行 |
| 390〜429px | 武器パネルは横スクロール、ボス帯は2行 |
| 389px以下 | ゲーム盤面と操作パネルを縦積みし、文字を省略しない |

## アクセシビリティ

- 武器ボタン、ボム、開始、スキップ、リトライに日本語の`aria-label`を設定する。
- 色差だけで武器状態やボスHPを表現しない。
- ボスの警告フェーズは色とアニメーション速度だけに依存せず、画面上に警告ラベルを出す。
- `prefers-reduced-motion` が有効な場合、発光・揺れ・ワープ演出を短縮または静止させる。
- タッチターゲットは44px以上を目安にする。

## 実装単位

- `GameHud`: Progress、Score、Coin、Life、Barrier
- `WeaponPanel`: 解放状態、現在選択、切替操作、コスト
- `BossBanner`: ボス名、HP、攻撃ラベル、Final表示
- `TouchPanel`: 移動、SHOT、BOMB、武器切替
- `EnemyView`: SVGボス本体と表示用の装飾

## 受入条件

- Desktop 1280x720でHUD、盤面、武器パネルが重ならない
- Mobile 390x844で盤面、武器切替、SHOT、BOMBが固定ナビに隠れず操作できる
- Mobile 390x844で `LIFE n/10` と残数ピップが盤面上部に常時表示される
- ボス名とHPがボスSVGに隠れない
- ボス帯とボスSVGが交差せず、ボスの絵柄全体を視認できる
- 中間ボスHPが30以上、ステージボスHPが80以上で、各カテゴリがステージ順に増加する
- ボスが画面外へ再登場しても、同じチェックポイントの残HPを引き継ぐ
- Mode 1〜5を開始前に選択でき、敵密度・通常敵HP・ボスHP倍率が順に増える
- Desktop 1280x720でゲーム盤面が従来より大きく、盤面と操作パネルが重ならない
- Mobile 390x844でスティックをドラッグして4方向へ移動でき、指を離すと停止する
- 武器の現在選択、未解放、コイン不足が視覚と読み上げで区別できる
- Stage 10でFinal Boss表示が出る
