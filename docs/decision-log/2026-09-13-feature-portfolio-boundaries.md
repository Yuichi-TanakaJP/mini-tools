# 機能ポートフォリオの3所属と評価語を固定する

Date: 2026-09-13

## 結論

機能見直しは「通常」「Premium投資」「Workspace」の3所属で行う。実装の存在、ライブ稼働、利用実績、完成度を混同せず、`実装済み`、`静的のみ`、`合成表示あり`、`要確認`を併記する。利用実績を確認できないことだけを理由に廃止しない。

全機能の現在地と候補は [機能ポートフォリオ台帳](../specs/cross-cutting/feature-portfolio.md) を正とする。

## 背景

通常ホームとPremiumホームには、単独ツール、投資判断ワークスペース、個人開発運用画面が並存している。URLだけで分類すると、Premium認証を持つ `/tools/yutai-dashboard` や、Supabase認証を持つ通常の銘柄分析を正しく説明できない。

また、コードが存在することから本番データ到達や利用を推測すると、静的棚卸し画面や未完成のPortfolioを完成済みと誤認する。

## 決めたこと

- 所属はURLではなく利用目的、得られる結果、認証境界で判定する。
- Premium投資とWorkspaceは同じPremium Cookieを使っても、成果物が投資判断か開発運用かで分ける。
- `実装済み`はコード/仕様上の状態であり、本番稼働・利用実績の証明に使わない。
- 静的定義だけを表示する機能は`静的のみ`と明記する。
- 固定の例示値を表示する経路がある機能は`合成表示あり`と明記し、ライブデータと区別する。
- 本番到達、利用状況、正本同期を確認していない場合は`要確認`とする。
- 候補ラベルは次の議論の入口であり、この文書だけで統合・分割・廃止を実施しない。

## 影響範囲

- このPRはdocsのみで、コード、導線、認証、保存先を変更しない。
- 次のPR以降は台帳のP0から、正本・責務・deep linkを小さく決める。
- 所属変更や廃止は、利用状況と本番状態を確認したうえで別Decision Logに残す。
