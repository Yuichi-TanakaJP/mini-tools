# 2026-09-14 機能ポートフォリオの3所属と存廃判断の境界

## 背景

通常ツール、Premium投資画面、開発・運用管理画面が同じアプリ内にあり、似た名前や同じデータを使う画面が増えた。URL階層だけでは、誰のどの判断を助ける機能か分かりにくい。

## 決めたこと

- 機能を「通常」「Premium投資」「Workspace」の3所属で整理する。
- 所属はrouteではなく、主目的・得られる結果・保存責務・認証境界で決める。
- 同じデータを使っても、探索、個別判断、全体判断、運用監視の結果が異なれば直ちに重複扱いしない。
- routeと主要処理を確認した「実装済み」を、本番稼働・利用頻度の証拠と区別する。
- 同梱・静的台帳だけに依存するものは「静的のみ」、運用や利用状況を確認できないものは「要確認」とする。
- 利用状況を示す証拠がない機能を推測で廃止・統合しない。

## 理由

機能数だけで整理すると、マイ銘柄・銘柄分析・保有銘柄分析、優待4機能、通常TOPIX33・Premium業種モメンタム、TDNET一覧・開示レーダーのような、同じ対象を異なる工程で扱う機能を誤って重複と判定するためである。一方、利用実態を確認しないまま維持を確定することも避け、未確認事項を台帳に残す。

## 影響範囲

- 現行route、認証、保存先は変更しない。
- 今後のナビ整理、計測、統合候補の評価は [`機能ポートフォリオ台帳`](../plans/function-portfolio-review.md) を入口にする。
- 存廃、URL移動、認証変更、保存正本変更は別の判断・PRで扱う。

## 再検討条件

- privacyを守った利用計測または明確な利用記録が得られた
- 2機能が同じ目的・結果・保存責務を持つことが確認された
- upstream停止や保守不能により、実装済みでも結果を提供できなくなった
- PremiumまたはWorkspaceのプロダクト境界を変更する合意ができた
