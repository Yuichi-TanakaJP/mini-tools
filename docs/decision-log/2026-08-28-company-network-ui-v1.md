# 2026-08-28 企業関係マップ V1 の表示・取得方針

## 結論

`/premium/company-network` を追加し、Supabase の企業関係グラフを読み取り専用で可視化する。
V1 では current な企業間関係と企業グループ所属を RLS の効く `security_invoker` View から
Server Component で一括取得し、画面内の 1-hop / 2-hop 探索はクライアント側の純関数で行う。

## 表示する関係

企業間関係は少なくとも次の3カテゴリを明示的に分ける。

- `capital`: 出資・持分法等の資本関係
- `control`: 親会社・支配等
- `historical`: 分社・前身・統合等の履歴

企業グループ所属は企業間エッジとは別ノード・別エッジとして表示する。
財閥・系列・企業グループを、親子会社関係と同一視しない。

## 事実と解釈

UI は `verification_status`、`confidence`、`source_as_of`、根拠 URL を表示する。
「文化的に近い」「関連が強い」等の推測スコアは V1 では作らない。
`proposed` を表示する場合は `verified` と見た目を分ける。

## 一括取得を選ぶ理由

V1 の関係数は小さく、企業ノードをクリックして中心を切り替える操作を即時に行えることを優先する。
取得上限は各層 2,000 行とする。

Supabase には `stock_notes_company_network(...)` RPC も用意済みで、最大2-hop・カテゴリ・verified・current
の絞り込みを RLS 維持のまま実行できる。関係数が増えて一括取得コストが無視できなくなった場合は、
UI の操作単位でこの RPC を呼ぶ方式へ切り替える。V1 の BFS ロジックは独立モジュールにしておき、
表示ロジックとデータ取得方式を密結合させない。

## V1 の操作

- 中心企業を選択
- 1-hop / 2-hop 切替
- 資本 / 支配 / 歴史カテゴリ切替
- verified のみ / proposed を含む切替
- 企業グループノードの表示切替
- 企業ノードをクリックして中心を変更
- 表示中の関係から根拠・基準日を確認

## 今回含めないもの

- ポートフォリオ集中度の計算（Phase 5）
- テーマからの二次受益候補推論（Phase 5）
- 顧客・供給・共同研究等の V2 関係（Phase 6）
- グラフの物理シミュレーション配置
- 大規模ネットワーク向けの逐次 RPC 取得
