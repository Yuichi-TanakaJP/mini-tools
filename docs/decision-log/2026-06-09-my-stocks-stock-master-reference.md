# My Stocks Stock Master Reference

Date: 2026-06-09

## Decision

`my-stocks` の公開基盤情報は `MARKET_INFO_API_BASE_URL` が設定されている場合、`GET /stock-master/latest` を優先して取得する。

API が未設定または取得失敗した場合は、従来どおり優待 month API と決算カレンダー API から code map を合成する fallback を残す。

画面には保存対象の `保有メモ` / `ウォッチ` に加えて、保存形式を変えない表示専用タブ `銘柄一覧` を追加する。`銘柄一覧` は client 側の銘柄マスターを一覧・検索し、各行から保有またはウォッチへ追加できる。件数が多いため、50件単位のページ送りを持つ。

## Reason

`market_info` 側で JPX 銘柄マスター、決算予定、優待、配当利回りを結合した stock master を publish できるようになったため、mini-tools 側で複数 endpoint を読んで同じ基盤情報を再構成するより、latest reference artifact を優先するほうが軽く、表示項目も揃えやすい。

## Impact

- `my-stocks` は次回決算・優待月に加えて配当利回りと推定年間配当を badge 表示できる。
- `銘柄一覧` では配当利回りと配当額を分けて表示する。
- `dividend_per_share` は確定配当ではなく `market_info` 側の利回り・株価からの逆算推定値として扱う。
- `銘柄一覧` タブは表示専用で、localStorage の `tab` 値は `holding` / `watch` のまま維持する。
- stock-master API が取得できた場合は、その records を配当付きの銘柄一覧として使う。
- 銘柄名の全角英数字は `market_info` の stock master artifact 側で半角化する。mini-tools は `/data/jpx_listed_companies.json` fallback にも同じ表示変換を適用する。

## 2026-09-20追記: コード撤去後にも残す設計思想と制約

利用者から、旧コードそのものよりも「どの情報をどう組み合わせて銘柄マスターを作ったか」と、有料情報を取得せず工夫して成立させようとしていた事情を残すよう明示された。本節は旧実装の記録であり、新画面の実装完了を意味しない。

### 背景

- 有料の包括的な市場データを購入する前提を置かず、利用可能な公開情報と既存の取得・配信経路を組み合わせて、必要な銘柄情報を揃えようとしていた。これは利用者が今回明示した設計背景である。
- 情報が一か所で完全に揃うわけではなく、取得範囲、更新時点、欠損、推定による代替という制約を引き受ける必要があった。無料情報だけで網羅性・鮮度・精度が保証されるという設計ではない。
- 利用者の目的は、保有だけでなく全銘柄の基礎情報を一か所で見渡すこと。保存先や取得元の違いを理由に閲覧画面まで分散させることが目的ではない。
- 公開閲覧できることと、無制限な取得・再配布が許されることは別。再利用時には各取得元の規約と利用可能範囲を確認する。

### 旧実装の情報経路

| 段階 | 情報経路・役割 |
|---|---|
| 基礎・参照情報の集約 | market_info側でJPX銘柄マスターに決算予定・優待・配当利回りを銘柄コードで結合し、`GET /stock-master/latest` として配信 |
| 通常経路 | MiniToolsの `loadMyStocksReference` が上記APIを優先取得。コード・名称・市場・業種と、決算日・優待月・配当情報のコード別対応表を生成 |
| API未設定・取得失敗時 | 既存の優待月別manifest/各月データから権利月を集約。決算カレンダーの月別/latestデータからJST当日以降で最も近い予定日を選択 |
| 銘柄検索の補完 | API由来マスターがない場合、`/data/jpx_listed_companies.json` をクライアントで一度取得してメモリに保持。コード前方一致・名称部分一致で検索 |
| 全銘柄表示 | 表示専用の「銘柄一覧」タブで検索・50件単位のページ送り。個人の保有・ウォッチに未登録でも一覧対象となる |
| 個人情報との結合 | 広く取得した参照情報をブラウザー内で保有・ウォッチのコードに照合。個人の保有コードや検索語を参照情報取得のために送らない |
| 配当額の概算 | 配信された1株年間配当推定値に保有数量を掛け、銘柄別・口座別の推定配当を集計。取得額は数量×取得単価で別集計 |

### 再利用時に忘れてはいけない限界

- 旧 `dividend_per_share` は利回り・株価から逆算した推定値であり、企業が公表する確定配当そのものではない。受取額や税引後額の保証にも使わない。
- fallbackには配当情報がなく、JPX同梱マスターだけでは決算・優待・配当を全件補完できない。
- API全体が取得できた場合、個々の欠損項目をfallbackで埋める実装ではなかった。
- 取得失敗時に対応表を空にし、バッジを表示しない設計だったため、「該当なし」と「取得できない」が見た目で区別しにくかった。
- fallbackの `asOf` は処理日のJST日付で、情報元がその日に更新された証拠ではない。APIの全体基準日も各項目の鮮度を一律に保証しない。
- 将来の全銘柄マスターでは、この集約思想を引き継ぎつつ、出典・基準日・推定/実績・未取得を区別する。旧保有の二重管理や古い値の上書きは復活させない。
