# 2026-09-09 カレンダーDB接続の段階導入

## 背景

Supabaseを唯一の正本にする6工程のうち、共通取得・保存層はPR593で完了した。
工程4で既存画面を接続する。全画面の切替が揃う前に本番の保存先は変更しない。

## 決めたことと理由

- カレンダーから接続し、明示的な隔離検証フラグの内側に置く。他画面と旧同期が残る
  途中状態を本番運用へ持ち込まないため。工程4の完了条件自体は縮小しない。
- 新規profileは承認済みの未設定/★★を使う。既存設定は保持する。
- カードの月設定はprofile/月を必要に応じて作る。月を外してもprofile・履歴・残高は
  削除しない。旧版の「単月メモは削除」とは意図的に異なる。
- 複数commandを一括保存と呼ばない。成功済みの件数を示して再開する。
  DB APIを増やさず、既存のrequest ID再送・revision競合防止を使う。
- 外部AIレビュー/サブエージェントはユーザーの使用禁止指示に従い使わない。
  差分の自己確認、単体テスト、ブラウザテスト、buildを実施し、独立レビューと混同しない。

## 影響と残課題

検証フラグ未設定の従来保存は維持する。DB migrationや本番データ変更は含まない。
工程4の残りはメモ帳本体・ダッシュボード・期限/残高・通知接続、旧書き戻し経路の排除。
その後の工程5（実端末/ChatGPT/復旧UAT）と工程6（最新差分照合・同時切替）は未完了。
