# 2026-09-11 旧トークン値の残骸を落とし、テーマ UAT を用意する

## 背景

トークンを整え、画面の直書き色を移行し、グラフ色と影も寄せた。
それでも accent の**旧実値** `#2554ff` が 24 箇所残っていた。

残っていたのは、これまでの移行が届かない書き方だった。

- SVG の属性（`stroke="#2554ff"` / `fill={...}`）
- グラデーション文字列の中（`linear-gradient(135deg, #1d44d8 0%, #2554ff 60%, ...)`）
- CSS モジュールのローカル変数（`--network-blue: #2554ff;`）

accent は `#265adf` に変わっているので、**同じ画面にボタンの青と図の青が 2 種類出ていた**。
利用者が最初に言っていた「統一感がない」の、いちばん分かりやすい形が残っていたことになる。

ヒーロー背景のグラデーションにも旧ページ色 `#eef2f7` が 3 箇所残っており、
地の色だけ更新されない状態だった。

## 今回決めたこと

- 旧トークン値を全て現行トークンへ置換する（SVG 属性・グラデーション・ローカル変数を含む）。
- **旧値が再び入らないよう `lib/__tests__/no-stale-theme-colors.test.ts` で守る。**
  トークンの実値を変えたら、旧値をこのテストへ追加することを運用として固定する。
- ローディングのスケルトンとヒーローのぼかしもトークンへ寄せる。
- 配色変更時の確認手順を [UAT: 表示テーマ](../uat/color-theme.md) として用意する。
  **Light / Dark の両方を通す**ことを手順に明記する。
- 管理画面 `app/admin/page.tsx` は引き続き対象外とする。常時 Dark なので、
  テーマ依存トークンを入れるとライト選択時に「暗い地に暗いリンク」になる。

## 判断理由

- 移行が「プロパティ: 値」の形だけを見ていたため、SVG 属性やグラデーション文字列を拾えなかった。
  同じ取りこぼしは値を変えるたびに起きるので、個別に直すのではなく、
  **旧値のリストを持ってテストで落とす**形にしたほうが再発しない。
- UAT を用意したのは、この種の不具合が「ライトでは正常・ダークでのみ不可読」という
  片側だけ壊れる形で出るため。片方だけ見て通す運用だと必ず漏れる。

## 影響範囲

- 旧値 29 箇所を置換（`#2554ff` 24 / `#eef2f7` 3 / `#1d44d8` 2）。
- company-network / industry-map の図色、ログインのグラデーション、
  各ツールのヒーロー背景、共通ローディングスピナー。
- 新規テスト `no-stale-theme-colors`（8 件）。
- 新規 `docs/uat/color-theme.md`。

## 残課題

- 管理画面を常時 Dark の公式な例外として仕様に書くか、選択テーマへ対応させるか。**要判断。**
- yutai-memo のタグ分類色（violet / sky）を役割トークンへ寄せるか、独立した分類パレットにするか。**要判断。**
- ゲーム以外に残る装飾グラデーション（premium 入口のヒーローなど）の扱い。
- 用意した UAT の初回実施。
