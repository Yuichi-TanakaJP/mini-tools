# 2026-09-09 メモ帳のタグ操作を既存commandへ接続

## 背景・判断

工程4のメモ基本編集（PR595）に続き、タグ作成/名称変更/削除/付与を接続する。
既存のcreate_tag/update_tag/delete_tag/set_profile_tagsを使い、DB schemaや権限を変更しない。
フォームを開いたrevisionを固定し、競合時に別端末の付与を上書きしない。

## 影響範囲

付け外しは一銘柄のみ。タグ削除は確認後にタグと全付与を削除する操作であり、
銘柄メモ、月別設定、仕込み履歴、優待残高は削除しない。
旧LocalStorageのタグ自動移行・保存処理を起動せず、本番環境変数は変更しない。
共通runnerの保存結果不明/読戻し失敗/本人切替時の停止を利用する。
タグと付与は読み取りだけでなく編集可能になったが、全年度履歴の表示専用は継続する。

## 検証・残件

単体で差分と対象/revisionを検証し、合成データのブラウザ試験で作成→付与→名称変更→削除を確認する。
サブエージェント・外部AIレビューはユーザーの使用禁止指示に従い使わない。
本番DBは読み取り診断だけで、実書込み/UATは工程5。工程4の履歴/一括操作等と他画面接続は残る。
