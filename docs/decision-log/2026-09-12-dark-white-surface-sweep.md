# 2026-09-12 ダークに残っていた白い面を洗い出して消す

## 背景

優待ダッシュボードで「カードの背面が白い」という指摘を受け、全画面を監査した。

## 見つけた最大の原因: 監査自体の穴

これまでの移行と `color-literal-budget` テストは **`#hex` しか数えていなかった**。
そのため次の 2 種類を丸ごと取りこぼしていた。

### 1. `rgba(255,255,255,0.x)` で書かれた白い面

33 箇所あった。とくに優待期限チェッカーは 23 箇所で、カードの大半がこの形。
`#hex` で検索しても 1 件も出てこないので、これまでの監査は「きれい」と報告していた。

### 2. 文字列連結の中の色

指摘のあった優待ダッシュボードの地は、これだった。

```js
background:
  "radial-gradient(...), " +
  "radial-gradient(...), " +
  "#f1f5f9",          // ← ページの地が白のまま
```

`background:` の直後に色が来ないため、プロパティ隣接で判定していた移行パスが
すべてすり抜けていた。カードはトークンで暗いのに、その背面だけ白い状態だった。

## 今回やったこと

- 明るい色リテラル（`#hex` と `rgb()` の両方、輝度 0.55 超）を全部列挙して 1 件ずつ判断した。
  **142 箇所 → 57 箇所。**
- 半透明の白い面は `color-mix(in srgb, var(--color-bg-card) N%, transparent)` へ。
  透過の見た目を保ったままテーマへ追従する。
- ページの地は距離ではなく役割で `--color-bg` に統一した（8 画面）。
  `#f1f5f9` は距離だけ見ると `bg-input` が最寄りだが、役割はページの地。
- `color-literal-budget` テストが `rgb()` / `rgba()` も数えるようにした。

## 触らなかったもの（残る 57 箇所）

数を 0 にはしない。次は**テーマに追従しないのが正しい**。

- **ヒートマップの自動コントラスト**（日経寄与度、TOPIX33、マーケット）。
  セルの明度から文字色を計算しており、`luminance > 0.62 ? "#0f172a" : "#f8fafc"` という
  ロジック自体が正しい。トークン化すると壊れる。
- **常時暗いヒーロー・パネルの上の白い文字と薄膜**（premium 入口、ポートフォリオ、
  優待候補の通知バー）。地が両テーマとも暗いので白のままが正しい。
- **ブランド寄りの装飾グラデーション**（ログイン、premium 入口）。
- `theme-color` の meta とテーマ選択 UI の値。

## 自分のミスと差し戻し

自動変換で、**常時暗いパネルの上の白い薄膜**（`rgba(255,255,255,0.08〜0.18)`）まで
`--color-bg-card` の `color-mix` に変えてしまい、ダークで効かなくなる状態を作った。5 箇所を白へ戻した。

透明度が低い（0.2 以下）白の重ねは「面」ではなく「持ち上げ」であることが多い。
この見分けは自動化しきれないので、仕様に例外として明記した。

## 残課題

- [UAT: 表示テーマ](../uat/color-theme.md) の実施。とくに優待期限チェッカーは
  カードの大半が今回 `color-mix` に変わったので、実機での確認が要る。
- ポートフォリオのヒーローにある損益色（`#86efac` / `#fca5a5`）は
  常時暗い面の上なので触っていないが、rise / fall との関係は整理の余地がある。
