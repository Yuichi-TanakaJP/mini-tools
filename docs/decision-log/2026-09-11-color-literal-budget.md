# 2026-09-11 一点ものの色を役割トークンへ寄せ、直書きを増やさない仕組みにする

## 背景

旧トークン値を掃除したあとも、非例外のファイルに色リテラルが 543 箇所残っていた。
中身を見ると、これまでの移行が「値の対応表」で進めてきたために拾えないものだった。

`ProductPortfolioCockpit.module.css` では、同じ「補助文字」の役割に
`#7a8495` `#7b8797` `#748093` `#748092` `#9aa4b2` `#919aa7` の**6 種類の近似グレー**が使われていた。
一点ものなので対応表には載らない。

## 今回決めたこと

### 対応表ではなく「最も近い役割トークンへ寄せる」

プロパティごとに候補トークンを絞り（`color:` は文字系、`background:` は面系…）、
Oklab 上の距離が 0.055 以内なら寄せる。超えるものは報告して個別に判断する。
結果 173 箇所を寄せた。

ただし**色の近さから役割を推定してはいけないもの**は候補から外した。

- **騰落（rise / fall）**: リンクの青と「下落」の青は色が近くても別の役割。
  実際、`#3b6de0`（リンク色）が `--color-fall` に寄る判定が出たので外した。
- **グラフ系列（fill / stroke）**: 分類色であり、意味で割り当てる。
- **白以外の境界線 → `bg-card`**: 薄いグレーの境界が白に寄ると線が消える。
  白いリング（`#ffffff` ちょうど）だけ許可する。

### 濃い面の役割を追加する

`--color-bg-emphasis` / `--color-text-on-emphasis` を追加した。

直書きの濃い面（`#0f172a` / `#102033`）に `--color-text-inverse` が乗っている箇所が 4 つあり、
**Dark で「暗い面に暗い文字」になって読めなくなっていた**。
`text-inverse` には対になる面のトークンが無く、役割として欠けていたのが原因。

Light では白い面が突然現れないよう、Dark でも濃いまま（page より一段明るい）にする。

### 直書きを増やさない

`lib/__tests__/color-literal-budget.ts` にファイル別の残数を持ち、
テストで「新規ファイルに色を書いた」「既存ファイルで増えた」を落とす。
減らしたときは予算も下げる。

## 判断理由

- 対応表方式は、同じ値が繰り返し出るうちは有効だが、一点ものには効かない。
  距離で寄せる方式なら、値を列挙しなくても役割へ集約できる。
- ただし距離だけに任せると役割を取り違える。**色が近い＝役割が同じ、ではない**。
  騰落とリンクの青が典型で、ここは人が決める領域として明示的に除外した。
- 配色の統一は一度やって終わりではなく、新しい画面を書くたびに崩れる。
  予算テストは「今ある分を直す」ためではなく「これ以上増やさない」ためのもの。

## 影響範囲

- 173 箇所を役割トークンへ。非例外の色リテラルは 543 -> 352 箇所（44 ファイル）。
- 新トークン: `--color-bg-emphasis` / `--color-text-on-emphasis`。
- 新規テスト: `color-literal-budget`（3 件）。
- 混在ブロック監査は 9 件 -> 1 件（yutai-memo のタグ分類色、方針未決のため据え置き）。
