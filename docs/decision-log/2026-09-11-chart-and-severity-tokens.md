# 2026-09-11 グラフ色を「分類」と「順序」に分け、影を 3 段へ寄せる

## 背景

画面の直書き色を移行したあと、残っていたのはグラフ系列の色配列・状態バッジ・影だった。
調べると次の 3 つが混ざっていた。

- 系列色の配列が画面ごとに独自定義（`SEGMENT_COLORS` / `CHART_COLORS` / `STOCK_CHART_COLORS`）。
  同じ「1 本目の系列」でも画面をまたぐと別の青になっていた。
- 経済指標の重要度（5 段階）を、分類用の色で表していた。
- 影が 79 箇所 41 種類。`0 8px 24px rgba(15,23,42,0.05)` のような値がその都度書かれていた。

## 今回決めたこと

### グラフ色は分類と順序を分ける

- 分類（順序のない区別）は `--color-chart-1` ～ `6`。系列が 6 を超える場合だけ
  `--color-chart-7` ～ `12` を使う。拡張分は既存 6 色の**中間の色相**として生成し、
  6 色以内で足りる画面の見た目を変えない。
- 順序（強弱に意味がある段階）は `--color-severity-1` ～ `5` を新設する。
  1 が最も弱く 5 が最も強い。**強さは明度差ではなく彩度で伝える**ので、
  1・2 は中立色、3 以降が警告色になる。

### 影は 3 段へ寄せる

`--shadow-card` / `--shadow-card-hover` / `--shadow-panel` の 3 段に寄せた。判定は用途で行う。

| 条件 | 段階 |
|---|---|
| hover / active の文脈 | `--shadow-card-hover` |
| 濃い影（alpha 0.15 以上） | `--shadow-panel` |
| それ以外 | `--shadow-card` |

focus リング（`0 0 0 Npx`）と `inset` は elevation ではないので対象外。

## 判断理由

- 順序尺度を分類色で表すと「色が違う＝別カテゴリ」に見え、段階であることが伝わらない。
  重要度 5 と 4 が赤と橙なのは偶然そう見えるだけで、規則になっていなかった。
- 拡張系列を既存 6 色の**中間**の色相にしたのは、`chart-1` ～ `6` の値を動かさずに
  12 系列まで伸ばすため。既存画面の見た目を変えずに上限だけ上げられる。
- 影を用途で判定したのは、ぼかし半径だけで見ると「resting なのに大きい影」を
  hover と誤判定するため。実際 `0 10px 30px` は resting のカードに使われていた。

### severity の単調性はコントラストで測らない

最初 `theme-contrast.test.ts` に「1 -> 5 でコントラスト比が単調に上がること」を書いたが、
Dark で落ちた。同じ明度なら赤は橙より輝度が低いためで、配色の誤りではない。
順序尺度の「強さ」は輝度比ではなく彩度に出るので、
**彩度が単調に上がること**と**隣どうしが dE 0.03 以上離れていること**を見る形に直した。

## 影響範囲

- `app/globals.css`: `--color-chart-7` ～ `12`、`--color-severity-1` ～ `5` を追加。
- 系列色: investor-flow / premium market / my-stocks。
- 状態バッジ: routines / themes / stock-notes（`rgba(...,0.14)` の背景も状態トークンへ）。
- 重要度: econ-calendar。
- 役割色: industry-map の `ROLE_COLOR`。
- 影: 26 ファイル 53 箇所（card 41 / panel 8 / hover 4）。

## 残課題

- グラデーション（ヒーロー・ログイン・premium 入口など）の扱い。装飾なので急がないが、
  accent トークンから導ける形にはできる。
- 管理画面 `app/admin/page.tsx` を常時 Dark の公式な例外として確定するか。
- yutai-memo のタグ分類色（violet / sky）。
- 全画面の Light / Dark UAT。
