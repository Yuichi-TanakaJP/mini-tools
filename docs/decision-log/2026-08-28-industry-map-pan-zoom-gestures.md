# 業界マップの拡大縮小と、ページスクロールとの住み分け

## 結論

放射マップと関係ネットワークに拡大縮小・移動を入れる。ただし**素のホイールとスマホの1本指操作はページに残し**、図が操作を奪うのは「ユーザーが拡大する意思を示したあと」に限る。

## 背景

領域が115ある半導体マップは、全体を1画面に収めるとラベルが小さく読みづらい。図を拡大できる必要がある。

一方この画面は縦に長く（ヘッダー・ツールバー・図・詳細パネル）、図は横幅いっぱいを占める。素直に「ホイールで拡大」「1本指ドラッグで移動」にすると、**図の上でページをスクロールできなくなる**。特にスマホでは画面の大半が図になるため、下へスクロールする手段が失われる。

## 決めたこと

| 操作 | 割り当て | 理由 |
|---|---|---|
| ＋ / − / ⟲ ボタン | 拡大・縮小・リセット | 発見しやすく、ホイールもタッチも要らない |
| ホイール単体 | ページの縦スクロール | 図の上でもページを読み進められる |
| Ctrl / ⌘ + ホイール | ポインタ位置を固定して拡大縮小 | 地図系UIの慣習 |
| ダブルクリック | その位置で1段階拡大 | ボタンへ手を動かさずに寄れる |
| マウスドラッグ | 図の移動 | ページの縦スクロールと競合しない |
| タッチ（等倍時） | `touch-action: pan-y`。1本指は画面スクロール | スクロール手段を奪わない |
| タッチ（拡大後） | `touch-action: none`。1本指で図を移動 | 拡大したなら図を操作したいはず |
| ピンチ | 2本指の中点を固定して拡大縮小 | `pan-y` はピンチズームを無効化するので、こちらで受け取れる |

- 倍率は 0.5〜8 倍で頭打ちにする
- domain を切り替えたら等倍へ戻す
- ドラッグが6ユーザー座標を超えたら、そのあとのクリックで領域を選択しない

## 理由

拡大操作の入口を「ボタン」に置いたのが要。ホイールとタッチの既定をページ側に残しても、ボタンがあれば拡大できないユーザーが出ない。Ctrl+ホイールやピンチは、知っている人向けの近道として重ねるだけで済む。

`touch-action` を拡大状態で切り替えるのは、「等倍＝まだ読み進めたい／拡大後＝図を見たい」という状態の違いをそのまま操作の割り当てに反映したもの。⟲ で等倍に戻せば、ページのスクロールも戻る。

ドラッグとクリックをしきい値で分けるのは、図を動かしただけで詳細パネルが別の領域に切り替わるのを防ぐため。

## 影響と残課題

- ドラッグ後に既定のフォーカス枠が残る問題があったため、`:focus` の outline を消し、`:focus-visible` で明示的に出すようにした。キーボード操作の可視性は保つ
- 拡大縮小は放射マップと関係ネットワークだけ。階層・マトリクス・表はHTMLなのでブラウザのズームと既存のスクロールで足りる
