# 優待残高・期限のDB接続

## 背景

工程4の継続として期限帳を接続する。残高と履歴の整合性・再送を、旧LocalStorage側で再実装しない。

## 決定と理由

- 独立した検証フラグで旧ToolClientのマウントを避ける。本番のフラグ/DB/backupは変更しない。
- 既存reward command9操作を利用し、残高と履歴の原子的更新はDBへ任せる。
- 各フォームは編集開始時のrow/revisionを保持し、同じ意図の再送は同じ要求IDを利用する。
- 通常メタデータ編集と残高/単位変更を分離する。単位変更・削除・履歴取消・残高訂正は理由/確認付き。
- 金額2桁/整数枚数を検証し、精度が失われる値は丸めず拒否する。額面/期限の未設定と0を区別する。
- 本番ではなく合成RPCによる画面テストで、作成から削除まで、競合と応答喪失を確認する。
- 利用者の委任禁止を優先し、サブエージェント/Codex CLI reviewは起動しない。自己レビューと自動検証を行い、証跡はPR本文へ残す。

## 影響と残件

本番の旧保存動作は保持。DB検証画面は操作接続を優先しており、従来UIの集計/表・画像スキャン・入出力・通知は未接続。
これらと残る他画面の接続を工程4に保持する。工程5/6の受入条件や全体完成条件は削らない。

## 一覧表示接続の追記

カード/表の切替、期間と期限月、登録/企業名/期限の並べ替えを追加する。
理由は、DBの基本操作だけでなく既存一覧で探す操作も使えるようにするため。
表の詳細では既存カードと同じ操作要素を使い、別の保存経路を増やさない。
額面未設定を0にせず、期間件数と検索結果件数を区別する。表示状態はメモリのみで旧保存先へ書き戻さない。
金額/累計集計、スキャン、通知、一括操作等の残件は削らず、一覧表示の完了と全体切替完了を分ける。
