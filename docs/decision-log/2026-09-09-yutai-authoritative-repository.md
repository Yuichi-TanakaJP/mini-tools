# 優待データはSupabase正本、キャッシュは再取得可能な表示専用

## 背景

従来はスマホでMiniToolsを直接操作するため、LocalStorage先行保存とネットワーク復旧後の
同期が必要だった。今後はChatGPTへの音声入力から直接Supabaseを更新し、MiniToolsで
同じ記録を表示することを主な利用経路とする。独立した二つの保存先を同期する前提を外す。

## 決定

Supabaseを唯一の正本とし、MiniToolsの共通データ層に表示専用cacheを置く。
工程3はメモリcacheを採用し、30秒の通常再利用、画面復帰・手動・保存後の再取得を実装。
offlineは取得済みデータの閲覧に限定し、未送信データを別の正本として持たない。

## 理由

不要な二重保存と同期競合を減らしながら、画面間移動の毎回ロードを抑える。
ChatGPT更新と画面編集が並行する可能性自体は残るため、DBのrevision競合と要求ID再送は維持する。
通信断だけではDB保存の成否を確定できないため、「不明」「保存済み・再取得失敗」を明示する。
個人データの永続cacheを増やさず、logout時に確実に破棄できる範囲を最初の実装とする。

## 影響範囲

工程3は既存UIに未接続。既存データ、旧同期、backupは変更しない。
画面接続、実機UAT、最新差分照合と本番切替は工程4〜6。
永続offline cacheやRealtimeは必要性が判明した後の改善であり、切替の追加必須工程にしない。

仕様と実装入口は[共通データ層](../specs/cross-cutting/yutai-repository.md)。
