# 優待の一括切替と旧保存先の保護

9月1日以降未使用のため、同日のスマホexportを最新原本とすることをユーザーが明示した。
DBに保全済みの元bytesとSHA-256が一致し、同じデータの再投入はしない。
画面ごとの切替漏れを防ぐため単一ビルドフラグでread/writeと旧同期停止を同時に切り替える。
既存の個別previewは隔離試験用として残す。
旧データは削除せず保管。新APIへ接続できない時に旧保存先へ自動フォールバックしない。
旧端末バックアップの取込でも優待7キーは保持し、他ツールの処理を維持する。
本番有効化・実sessionの往復確認は別途証跡が必要で、このガード追加だけでは本番切替済みとはしない。
