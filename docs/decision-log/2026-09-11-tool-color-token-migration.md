# 2026-09-11 各画面の直書き色を役割トークンへ移行する

## 背景

同一 hue 軸のトークン基盤を入れても、`app` / `components` には色リテラルが 1,779 箇所・56 ファイル残っていた。
ダークテーマは共通シェルにしか届かず、ツール本体は明るいままだったため、
利用者から見た「統一感のなさ」はほとんどここが原因だった。

## 今回決めたこと

- 直書き色は **プロパティと値の組で役割が一意に決まるものだけ**を機械的に置換する。
  `color:` は文字・状態前景・accent、`background:` は面・状態背景、`border*:` は境界という対応で判断する。
- 判断に文脈が要るもの（グラフ系列、ゲーム、選択中を示す teal / sky など）は表に載せず、個別に確認して決める。
- 移行後は「同じスタイルブロック内にトークンと直書きが同居していないか」を機械的に監査する。
  ダークで「トークンの文字 × 直書きの明るい面」になる組み合わせが、いちばん壊れやすいため。
- 無効化された操作の文字用に `--color-text-disabled` を追加する。
  既存の 3 段（text / text-sub / text-muted）はいずれもコントラスト基準を満たす前提で、
  「あえて読みにくくする」役割が無かった。
- premium 画面の indigo（hue 277）は accent へ寄せる。独立した 4 本目の軸として残さない。
- 「選択中」を示していた teal `#0f766e` と sky `#0284c7` は info の役割として扱う。
- **常時 Dark 前提の画面（`app/admin/page.tsx`）は移行対象から外す。**

## 判断理由

- 1,779 箇所を目視で置換すると取りこぼしと誤変換が必ず出る。一方で全置換は
  「白背景に白文字」のような事故を生む。役割が一意に決まる組に限れば、機械的でも安全に倒せる。
- 混在ブロックの監査を入れたのは、移行の失敗が「ライトでは正常・ダークでのみ不可読」という
  気づきにくい形で出るため。ライトだけ見て通してしまう事故を防ぐ。
- 管理画面を外したのは、この画面の `#94a3b8` / `#64748b` が「暗い地に乗る明るい文字」だからで、
  同じ値でも役割が逆になる。機械的に `--color-text-muted` へ寄せると、ライトテーマで
  「暗い地に暗い文字」になって読めなくなる。実際に一度変換してしまい、差し戻して気づいた。
  値ではなく役割で判断する必要があることの実例として残す。
- disabled を text-muted で代用すると、無効な操作が有効に見える。
  逆に直書きの薄いグレーのままだとダークで消える。役割として切り出すのが正しい。

## 影響範囲

- 色リテラルは 1,779 → 900 箇所（52 ファイル）。うち意図的な例外が 380 箇所。
  - ゲーム（penguin 系）208: 仕様上の例外
  - 管理画面 74: 常時 Dark 前提のため据え置き（値の意味が他画面と逆になる）
  - `app/globals.css` 98: トークン定義そのもの
- 残る約 520 箇所は、グラフ系列の配列、影、グラデーション、SVG の fill / stroke。
- トークン参照は 1,897 箇所。

## 残課題

- グラフ系列の色配列（例: `SEGMENT_COLORS`）を `--color-chart-1`〜`6` へ寄せる。
  Canvas 描画では CSS 変数がそのまま使えないため、`getComputedStyle` で解決する経路が要る。
- 影・グラデーションを `--shadow-*` と accent トークンへ寄せる。
- 管理画面を常時 Dark の例外にするかを確定する。
- yutai-memo のタグ分類色（violet / sky）は利用者が選ぶ分類色であり、
  役割トークンへ寄せるか独立した分類パレットにするかは未決。今回は据え置いた。
- 全画面の Light / Dark UAT。
