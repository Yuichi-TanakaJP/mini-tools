# 2026-09-12 塗りつぶしマーク用の状態色を分ける

## 背景

優待ダッシュボードのカレンダーで「オレンジとグリーンが弱くなった」と指摘を受けた。
直書き色の移行（PR #616）で、カレンダーのマーク色を状態色トークンへ置き換えたのが原因。

| マーク | 旧 | 新 | 明度差 |
|---|---|---|---|
| 取得済み ✓ | `#16a34a` (L62.7 / C0.170) | `--color-success` `#00773b` (L49.9 / C0.131) | **−12.8** |
| 重複 | `#f59e0b` (L76.9 / C0.165) | `--color-warning` `#a55d00` (L55.0 / C0.127) | **−21.9** |

## 何を間違えたか

`--color-success` / `--color-warning` は **前景色**で、「明るい面の上に乗る文字・アイコン」
として読めるように**暗く**作ってある。それを 7〜12px の**塗りつぶしマークの地**に使った。

塗りは逆で、密なカレンダーの中で一目で気づける**鮮やかさ**が要る。
役割が違うトークンを、色の名前（success = 緑）だけで対応付けてしまった。

移行の判断を「プロパティ（`background:` なら面系）」で行っていたが、
状態色には「面」に当たるトークンが `-bg`（淡い背景）しかなく、
**塗りつぶしマークの地という役割が欠けていた**。そのため前景色へ寄せる以外になかった。

## 今回決めたこと

`--color-{info,success,warning,error}-solid` を追加する。

| | Light | Dark |
|---|---|---|
| info | `#5588c9` | `#6192cf` |
| success | `#00a151` | `#18aa5a` |
| warning | `#f58e00` | `#fd9929` |
| error | `#d95f6c` | `#e06b76` |

Light は旧実装とほぼ同じ鮮やかさに戻る（success 旧 L62.7/C0.170 → 新 L62.1/C0.164、
warning 旧 L76.9/C0.165 → 新 L74.1/C0.170）。

- 上に短いグリフを置く場合は `--color-text-inverse`。ライトでは白、ダークでは濃い字になり、
  どちらの地でも読める側へ倒れる。
- **長い文章は `-solid` に載せない。** 鮮やかさを優先しているため本文の 4.5:1 を満たさない
  組み合わせがある（特に warning は白文字で 2.4:1）。文章には `-bg` と `-text` の組を使う。

## 再発防止

`theme-contrast.test.ts` に「`-solid` は前景色より必ず彩度が高い」を追加した。
今回のミス（塗りに前景色を入れる）を再現すると落ちることを確認済み。

コントラスト比ではなく彩度で見ているのは、`-solid` の狙いが
「読めること」ではなく「一目で気づくこと」だから。明度比では表せない。

## 影響範囲

- `app/globals.css`: 状態色 4 families × 2 テーマ = 8 トークン追加。
- `app/tools/yutai-dashboard/ToolClient.tsx`: `calAcquiredMark` と `calOverlapDot`。
  （アプリ全体で状態色を塗りに使っていたのはこの 2 箇所だけ）

## 残課題

- 同じカレンダーの「準備完了」マークは `#c026d3`（C0.257）から
  `--color-chart-6`（C0.155）になり、彩度が落ちている。
  分類色としては chart-6 が正しい役割なので今回は触っていないが、
  他のマークが鮮やかさを取り戻した分、相対的に沈んで見える可能性がある。**要確認。**
