# 銘柄分析ダッシュボード UAT

## 前提

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` が設定されている。
- stock-notes（別リポジトリ）が同一 Supabase ユーザーとして `stock_notes_stocks` / `stock_notes_analyses` / `stock_notes_theses` / `stock_notes_actions` にデータを書き込んでいる。
- `my-stocks` の保有銘柄（`my_stocks_items_v1`）がクラウド同期でアップロード済み（`/account` から「この端末を保存」を実行済み）。

## 確認項目

### 正常系

- `/tools/stock-notes` にログイン後アクセスすると、未分析の保有銘柄・分析済み銘柄一覧・アクション受信箱の3セクションが表示される。
- 保有していて stock-notes に銘柄登録が無い、または分析0件の銘柄が「未分析の保有銘柄」に表示される。
- 「分析用プロンプトをコピー」を押すとクリップボードに `<コード> <銘柄名>について、直近の決算と現在の投資判断を整理して` がコピーされ、ボタン表示が一時的に「コピーしました」になる。
- 分類タブ（保有 / ウォッチ / 新規調査 / アーカイブ）を切り替えると、該当分類の銘柄だけが表示される。
- 一覧の行に、現在の見立て（強気/中立/弱気の色分け・確信度）、最終分析日、鮮度バッジ、分析件数、未消化アクション数、次回決算日（下記）が表示される。
- 最終分析日から90日超180日以内の銘柄に「そろそろ確認」バッジ、180日超に「要更新」バッジが表示される。ただし最終分析日より後に決算発表があった銘柄は、経過日数に関係なく「要更新（決算後未分析）」バッジが表示される（決算またぎ優先）。
- 行をタップすると詳細（現在の見立ての仮説・リスク・次回確認点・買い増し/撤退条件、分析タイムライン）が展開される。
- 分析タイムラインの初期表示では会話原文（body）が表示されない。「原文を表示」を押したときだけ原文が読み込まれて表示される。
- アクション受信箱に `status='open'` のアクションが期限昇順で表示され、期限切れのアクションが強調表示される。

### 次回決算日

- 未分析の保有銘柄・分析済み銘柄の各行に、次回決算日と残り日数が「次回決算 8/14（あと3日）」のように表示される。
- 決算が3日以内に迫っている銘柄が強調表示される。
- 未分析の保有銘柄リストが「決算が近い順」（決算日判明分を日付昇順、未判明分はコード順で後ろ）に並んでいる。
- カレンダーのウィンドウ内に予定が見つからず、月次データの取得が完全だった銘柄は「次回決算 未判明（カレンダーは9/30まで）」のように **`windowTo` の具体的な日付を含めて** 表示され、**「予定なし」とは表示されない**。
- `MARKET_INFO_API_BASE_URL` 未設定、または `/api/stock-notes/earnings` が取得に失敗する状況を意図的に発生させると、各行が「決算情報を取得できませんでした」と表示される（「未判明」とは区別される）。この場合でも「保有だが未分析」「分析済み銘柄」「アクション受信箱」の各セクションは通常どおり表示される（決算日の取得失敗だけでページ全体がエラー表示にならない）。
- `/api/stock-notes/earnings` で当月以外の月（前月・翌月・翌々月のいずれか）だけ取得に失敗する状況を意図的に発生させると、200は返るが `complete: false` になり、該当銘柄が「未判明」ではなく「決算情報を取得できませんでした（一部期間が未取得）」と表示される（欠落した月に決算が入っていた可能性を「未判明」と誤解させない）。
- 決算日が同日中に発表済み（`publish_status='発表済'`）になった銘柄は、翌日を待たずにその日のうちに鮮度バッジが「要更新（決算後未分析）」に切り替わる。

### 保有リストの同期状態

- 画面上部に「保有リストの同期: 2026-06-21（52日前）」のように、`/api/sync` の `my_stocks_items_v1` の最終同期日時が表示される。
- 同期から30日以上経過している場合、注意表示（マイ銘柄リストを更新した場合は `/account` の「この端末を保存」を押すよう促す文言）と `/account` への導線が表示される。
- 同期から30日未満の場合は注意表示が出ない。
- 一度も同期していない（`updatedAt` が無い）場合は「同期が30日以上前です」ではなく「保有リストの同期日時を確認できません」と表示される（30日という具体的な経過を誤って主張しない）。

### 未ログイン

- 未ログインで `/tools/stock-notes` にアクセスした場合、エラー画面にならず「ログインしてください」の案内と `/account` へのログイン導線が表示される。

### データ0件

- stock-notes 側にデータが1件も無いユーザーでログインした場合、「未分析の保有銘柄」「分析済み銘柄」「アクション受信箱」の各セクションに空状態メッセージが表示される。
- 保有銘柄（`my_stocks_items_v1`）が0件の場合、「保有銘柄が登録されていません」の案内が表示される。
- **ウォッチ銘柄しか登録が無い（`tab='watch'` のみ）場合も同じ「保有銘柄が登録されていません」の案内になる**（「保有銘柄はすべて分析済みです」という誤表示にならないこと）。

### 異常系

- Supabase 未設定の環境では「このツールは現在この環境では利用できません」と表示され、クラッシュしない。
- テーブル取得に失敗した場合、「データの取得に失敗しました」と再読み込みボタンが表示される。
- **`/api/sync` がセッション切れ等で401を返す状態**（例: 別タブでログアウトしてからこの画面で再読み込み）で `/tools/stock-notes` を開くと、一般的な「データの取得に失敗しました」ではなく「セッションが切れています。ログインし直してください」＋再ログイン導線が表示される。
- **未分析の保有銘柄が本来22件など多数あるユーザーで、`/api/sync` がエラーを返す状況を意図的に発生させた場合**、「保有銘柄が登録されていません」や「保有銘柄はすべて分析済みです」という0件表示には絶対にならず、エラー状態が表示される（保有0件と取得失敗を混同しないことの確認）。
- ログイン中に別アカウントへ切り替える、またはログアウトした場合、直前のユーザーの分析データが画面に残らない（ログアウト直後にデータが消え、別アカウントでログインすると新しいアカウントのデータだけが表示される）。

### スマホ表示

- 幅375px相当（iPhone SE 相当）で横スクロールが発生しない。
- カード・タブ・ボタンが画面幅に収まり、テキストが折り返される。
