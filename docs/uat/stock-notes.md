# 銘柄分析ダッシュボード UAT

## 前提

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` が設定されている。
- stock-notes（別リポジトリ）が同一 Supabase ユーザーとして `stock_notes_stocks` / `stock_notes_analyses` / `stock_notes_theses` / `stock_notes_actions` にデータを書き込んでいる。
- `my-stocks` の保有銘柄（`my_stocks_items_v1`）がクラウド同期でアップロード済み（`/account` から「この端末を保存」を実行済み）。

## 確認項目

### 正常系

- `/tools/stock-notes` にログイン後アクセスすると、保有リストの同期状態・銘柄一覧・アクション受信箱のセクションが表示される。
- 「要対応」タブ（既定表示）の行に「未分析」「{M/D}の決算後」「期限切れ」「期限間近」の理由バッジが該当する分だけ表示される（複数該当時は全て表示。下記「要対応タブの理由バッジ」参照）。
- 「要対応」タブの各行に「分析用プロンプトをコピー」ボタンがあり、押すとクリップボードに `<コード> <銘柄名>について、直近の決算と現在の投資判断を整理して` がコピーされ、ボタン表示が一時的に「コピーしました」になる（他の4タブの行にはこのボタンは表示されない）。
- 5タブ（要対応 / 保有 / ウォッチ / 新規調査 / アーカイブ）を切り替えると、該当タブの銘柄だけが表示される。既定表示は「要対応」タブ。各タブのラベルに件数が表示される（例: 「要対応 15」）。
- 一覧の行に、現在の見立て（強気/中立/弱気の色分け・確信度）、最終分析日、分析件数、未消化アクション数、次回決算日（下記）が表示される。「要対応」タブでは理由バッジ、他の4タブでは鮮度バッジが表示される（同時には出ない）。
- 「保有」「ウォッチ」「新規調査」「アーカイブ」タブでは、最終分析日から90日超180日以内の銘柄に「そろそろ確認」バッジ、180日超に「要更新」バッジが表示される。ただし最終分析日より後に決算発表があった銘柄は、経過日数に関係なく「要更新（決算後未分析）」バッジが表示される（決算またぎ優先）。
- 行をタップすると詳細（現在の見立ての仮説・リスク・次回確認点・買い増し/撤退条件、分析タイムライン）が展開される。展開部の末尾に分類変更セレクトと削除ボタンが表示される。
- 分析タイムラインの初期表示では会話原文（body）が表示されない。「原文を表示」を押したときだけ原文が読み込まれて表示される。
- アクション受信箱に `status='open'` のアクションが期限昇順で表示され、期限切れのアクションが強調表示される。

### 5タブ構成（要対応/保有/ウォッチ/新規調査/アーカイブ）

- 分析0件の銘柄、最終分析日より後に決算があった銘柄（決算またぎ）、期限切れ・期限間近（7日以内）の未消化アクションがある銘柄が「要対応」タブに表示される（アーカイブの銘柄は除く）。
- 「要対応」タブは**保有（`category='holding'`）を先頭に**、そのうえで次回決算日が近い順（未判明は後ろ）→最終分析日の古い順で並ぶ。保有ではないがウォッチ・新規調査の中に決算がより近い銘柄があっても、保有銘柄が優先して上に来る。
- 「保有」「ウォッチ」「新規調査」「アーカイブ」の各タブは、該当する `category` の銘柄だけが最終分析日の古い順（未分析が最上位）で表示される。
- アーカイブに分類した銘柄は、「要対応」を含む他のどのタブにも一切表示されない。

### 要対応タブの理由バッジ

- 分析0件の銘柄には「未分析」バッジが表示される。
- 最終分析日より後に決算があった銘柄には「{M/D}の決算後」（例: 「8/4の決算後」）バッジが表示される。
- 未消化アクションの期限が既に過ぎている銘柄には「期限切れ」バッジが表示される。
- 未消化アクションの期限がまだ過ぎていないが7日以内に迫っている銘柄には「期限間近」バッジが表示される。
- 複数の条件に該当する銘柄（例: 未分析かつ期限切れのアクションがある）には、該当するバッジがすべて表示される。
- 「保有」「ウォッチ」「新規調査」「アーカイブ」タブでは理由バッジの代わりに鮮度バッジが表示され、同じ銘柄の同じ情報（決算またぎ）が2種類のバッジで重複表示されることはない。

### 銘柄の登録

- 「＋ 銘柄を登録」を押すと登録フォームが開き、証券コード・銘柄名・分類（保有/ウォッチ/新規調査）を入力できる。
- 証券コードを入力すると、銘柄マスターに一致するコードがあれば銘柄名欄が自動補完される。
- マスターに無いコード（例: 米国株のティッカー）を入力しても、銘柄名を手入力すれば登録できる。
- 「登録する」を押すと `stock_notes_stocks` に新しい行が作成され、フォームが閉じて一覧に反映される（対象タブに表示される）。
- 既に登録済みの証券コードを入力して登録しようとすると、送信前にエラーメッセージが表示され登録されない。

### 分類変更・アーカイブ・削除

- 一覧行を展開し、分類セレクトで holding/watch/research/archived のいずれかに変更すると、即座に分類が変わり該当タブへ移動する。
- 分類を「アーカイブ」に変更すると、任意でアーカイブ理由の入力を求められる（空欄でも変更できる）。
- 分析が1件以上ある銘柄は削除ボタンが無効化されており、押しても何も起きない（無効化の理由が表示される）。
- 分析が0件の銘柄は削除ボタンが有効で、押すと確認ダイアログが表示され、確認すると銘柄が削除されて一覧から消える。
- 確認ダイアログでキャンセルすると、銘柄は削除されずそのまま残る。
- （開発者ツールや別クライアントから直接 `stock_notes_analyses` を追加するなどして）表示中のキャッシュ上は分析0件に見える銘柄を削除しようとし、DB側が外部キー制約（restrict）で拒否する状況を意図的に発生させると、生のデータベースエラーではなく「この銘柄には分析が残っているため削除できません。アーカイブしてください」というメッセージが表示される。

### マイ銘柄リストからの一括取り込み

- マイ銘柄リストの保有銘柄のうち `stock_notes_stocks` に未登録のものが1件以上あるとき、タブの外にバナー「マイ銘柄リストに未登録の保有が N 件あります」が表示される。
- 「まとめて登録」を押すと対象銘柄（コード・銘柄名・保有数量）の一覧が展開表示され、まだ書き込みは行われない。
- 「N件を『保有』としてまとめて登録」を押すと、対象銘柄が `category='holding'` でまとめて登録され、成功した件数が表示される。
- 一部の銘柄が登録に失敗した場合（例: 直前に他の経路で同じコードが登録された）、失敗した銘柄だけが個別にエラーメッセージ付きで表示され、成功した銘柄はそのまま登録された状態で残る。
- **全件成功して未登録の保有銘柄が0件になっても、バナーはすぐには消えない**。「一括登録が完了しました。」の見出しと成功件数・（あれば）失敗一覧が表示されたまま残り、「閉じる」を押すまで確認できる（消えたまま「実行したのに何も起きなかった」ように見えないことの確認）。「閉じる」を押すとバナー自体も消える。
- 「まとめて登録」を押して確認画面を開いた後、対象一覧を確認している間にバックグラウンド再取得（自動・「今すぐ更新」）が走っても、確認画面に表示されている対象銘柄一覧は変化しない（開いた時点でスナップショットとして固定されているため）。登録を実行すると、その固定された一覧のとおりに登録される。
- 別タブで先に同じ保有銘柄が `stock_notes_stocks` に登録済みの状態で「まとめて登録」を実行すると（＝この画面のキャッシュは未登録のまま）、対象銘柄は「既に登録されています」で失敗表示になるが、その後裏で再取得が行われ、次に見たときにはその銘柄がバナー対象から外れている（DBには反映済みなのに古いキャッシュの「未登録」表示が残り続けないことの確認）。

### 次回決算日

- 銘柄一覧の各行に、次回決算日と残り日数が「次回決算 8/14（あと3日）」のように表示される。
- 決算が3日以内に迫っている銘柄が強調表示される。
- 「要対応」タブが、保有を先頭にしたうえで「決算が近い順」（決算日判明分を日付昇順、未判明分は後ろ）に並んでいる（上記「5タブ構成」参照）。
- カレンダーのウィンドウ内に予定が見つからず、月次データの取得が完全だった銘柄は「次回決算 未判明（カレンダーは9/30まで）」のように **`windowTo` の具体的な日付を含めて** 表示され、**「予定なし」とは表示されない**。
- `MARKET_INFO_API_BASE_URL` 未設定、または `/api/stock-notes/earnings` が取得に失敗する状況を意図的に発生させると、各行が「決算情報を取得できませんでした」と表示される（「未判明」とは区別される）。この場合でも「銘柄一覧」「アクション受信箱」の各セクションは通常どおり表示される（決算日の取得失敗だけでページ全体がエラー表示にならない）。
- `/api/stock-notes/earnings` で当月以外の月（前月・翌月・翌々月のいずれか）だけ取得に失敗する状況を意図的に発生させると、200は返るが `complete: false` になり、該当銘柄が「未判明」ではなく「決算情報を取得できませんでした（一部期間が未取得）」と表示される（欠落した月に決算が入っていた可能性を「未判明」と誤解させない）。
- 決算日が同日中に発表済み（`publish_status='発表済'`）になった銘柄は、翌日を待たずにその日のうちに鮮度バッジが「8/4の決算後、未分析」のように決算日入りの文言に切り替わる。

### 前回決算日

- 前回決算が判明していて次回決算も判明している銘柄では、「前回決算 8/4（1Q）」のように区分つきで表示される（経過日数は付かない）。
- 前回決算が判明していて次回決算が未判明の銘柄では、「前回決算 8/4（1Q・7日前）」のように経過日数つきで、かつ目立つ色で表示される。
- 前回決算も判明していない銘柄では、前回決算の行自体が表示されない（「不明」とは表示されない）。
- 過去3ヶ月以内に決算があった銘柄（前回決算が当月＋前月の範囲に収まらない銘柄、例: 3ヶ月前の四半期決算）でも前回決算が表示される（当月＋前月だけの範囲では見つからなかったことの回帰確認）。

### 保有リストの同期状態

- 画面上部に「保有リストの同期: 2026-06-21（52日前）」のように、`/api/sync` の `my_stocks_items_v1` の最終同期日時が表示される。
- 同期から30日以上経過している場合、注意表示（マイ銘柄リストを更新した場合は `/account` の「この端末を保存」を押すよう促す文言）と `/account` への導線が表示される。
- 同期から30日未満の場合は注意表示が出ない。
- 一度も同期していない（`updatedAt` が無い）場合は「同期が30日以上前です」ではなく「保有リストの同期日時を確認できません」と表示される（30日という具体的な経過を誤って主張しない）。

### 未ログイン

- 未ログインで `/tools/stock-notes` にアクセスした場合、エラー画面にならず「ログインしてください」の案内と `/account` へのログイン導線が表示される。

### データ0件

- stock-notes 側にデータが1件も無いユーザーでログインした場合、「銘柄一覧」（各タブ「この分類の銘柄はまだありません」）「アクション受信箱」の各セクションに空状態メッセージが表示される。
- 保有銘柄（`my_stocks_items_v1`）が0件の場合、「保有」タブに切り替えると「この分類の銘柄はまだありません」の案内が表示される（一括取り込みバナーも対象0件のため表示されない）。
- **ウォッチ銘柄しか登録が無い（`tab='watch'` のみ）場合でも、「保有」タブは「この分類の銘柄はまだありません」のまま**（保有0件専用の文言は無いため、ウォッチのみのケースと区別されない。旧「保有だが未分析」セクション廃止に伴う仕様変更）。

### 異常系

- Supabase 未設定の環境では「このツールは現在この環境では利用できません」と表示され、クラッシュしない。
- テーブル取得に失敗した場合、「データの取得に失敗しました」と再読み込みボタンが表示される。
- **`/api/sync` がセッション切れ等で401を返す状態**（例: 別タブでログアウトしてからこの画面で再読み込み）で `/tools/stock-notes` を開くと、一般的な「データの取得に失敗しました」ではなく「セッションが切れています。ログインし直してください」＋再ログイン導線が表示される。
- **保有銘柄が多数あるユーザーで、`/api/sync` がエラーを返す状況を意図的に発生させた場合**、銘柄一覧やアクション受信箱が0件表示に化けることは絶対になく、エラー状態が表示される（保有0件と取得失敗を混同しないことの確認）。
- ログイン中に別アカウントへ切り替える、またはログアウトした場合、直前のユーザーの分析データが画面に残らない（ログアウト直後にデータが消え、別アカウントでログインすると新しいアカウントのデータだけが表示される）。

### キャッシュ（stale-while-revalidate）

- `/tools/stock-notes` に一度アクセスした状態でページを再読み込みすると、（TTL 15分以内であれば）ローディング表示（「データを取得中…」）を経由せず、直前の表示内容が即座に出る。その後、画面右上あたりに一時的に「更新中…」が表示され、裏で再取得が行われる。
- 再取得が成功すると「更新中…」が消え、「最終更新 HH:MM」の時刻が更新される。
- 「今すぐ更新」ボタンを押すと、キャッシュの有無に関わらず再取得が始まり（「更新中…」表示）、成功すると内容と「最終更新」時刻が更新される。
- ネットワークを切る、またはSupabase/`/api/sync`が一時的にエラーを返す状況を意図的に発生させてから「今すぐ更新」を押すと、画面は空白/エラー表示にならず直前の内容を維持したまま、「最新の取得に失敗しました（表示はHH:MM時点）」という案内が表示される。
- **別タブでログアウトしてからこの画面で「今すぐ更新」を押す**（＝裏の再取得が401で失敗する状況）と、通常の「取得に失敗しました」表示ではなく、他の401ケースと同じ「セッションが切れています。ログインし直してください」画面に切り替わる（表示中のデータは残らない）。
- ログアウトしてから同じ端末で別アカウントにログインし直すと、前のアカウントの銘柄・分析内容が一瞬でも画面に残らない（ローカルキャッシュもログアウト時に破棄されている）。
- ブラウザの開発者ツールで `localStorage` を確認すると、`stock_notes_dashboard_cache_v1_<userId>` のようなキーでダッシュボードのデータが保存されている（会話原文=`body`は含まれていない）。ログアウト後はこのキーが削除されている。
- TTL（15分）を過ぎた状態（例: PCの時計を進める、または15分以上経過を待つ）で再度アクセスすると、キャッシュは使われず通常どおり「データを取得中…」のローディング表示を経由して取得される。
- 素早くアカウントA→Bへ切り替える（Aでログイン直後、応答が返るより先にBへ切り替わるくらいのタイミング）と、最終的に画面にはBのデータだけが表示され、Aのuidでキャッシュが保存されない（開発者ツールで `localStorage` を確認し、`stock_notes_dashboard_cache_v1_<AのuserId>` が作られていない、または作られていても中身がBのものではないことを確認する）。
- Supabaseのセッションだけが期限切れになった状態（`stock_notes_*` の取得がPostgRESTの `PGRST301` 相当のエラーを返す状況）で「今すぐ更新」を押すと、`/api/sync` の401と同様に「セッションが切れています。ログインし直してください」画面に切り替わる（一般的な「取得に失敗しました」表示にはならない）。
- 「今すぐ更新」を連続で複数回押す、またはページ再読み込み直後にすぐ押すなど、再取得中に別の再取得が割り込む操作をしても、最終的に「更新中…」の表示が消えて通常表示に戻る（消えたまま固まらない）。
- 銘柄の登録・分類変更・削除・一括取り込みのいずれかを実行している最中（書き込み〜再取得の間）に別アカウントへ切り替えると、切り替え後の画面には切り替え後のアカウント（B）のデータだけが表示され、切り替え前のアカウント（A）のキャッシュ（`stock_notes_dashboard_cache_v1_<AのuserId>`）にBのセッションで取得したデータが保存されない（開発者ツールで確認する。実運用でタイミングを正確に合わせるのは難しいため、コードレビュー・ユニットテスト（`logic.test.ts` の `createLoadGuard` シナリオ3）での確認で代替してよい）。

### スマホ表示

- 幅375px相当（iPhone SE 相当）で横スクロールが発生しない。
- カード・タブ・ボタンが画面幅に収まり、テキストが折り返される。
