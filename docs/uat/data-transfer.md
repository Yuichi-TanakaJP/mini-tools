# データ入出力 UAT

## DB隔離検証

ローカル/Previewに `NEXT_PUBLIC_YUTAI_TRANSFER_DB_PREVIEW=true` とSupabase公開接続設定を指定する。
自動試験は `npx playwright test --config=playwright.yutai.config.ts yutai-transfer.spec.ts`。合成session/模擬DBのみを用いる。

1. 本人ログインでDB出力欄を開く。非表示銘柄、8月/9月の異なる設定、2025年/2026年履歴、タグ割当、archive済み残高、残高履歴、global/月別選択を用意する。
2. DB全件JSONをダウンロードし、全8種類の全フィールド・件数、NULL/0、小数、日時精度、ID/revisionが取得値と一致することを確認する。
3. 出力した同じJSONを読み込み「全件照合」で一致を確認する。ファイルに認証情報や他ツールのLocalStorageが混入しないこと。
4. 別端末相当の更新後に再照合し、対応する種類に内容変更件数が出ること。現在DBとファイルのどちらも書き換わらないこと。
5. 値を改変したJSON、配列欠落、件数不一致、ID重複、参照先欠落、旧形式、未知version、不正JSON、上限超過を拒否すること。
6. 別owner/projectのファイルは照合を拒否し、自動適用しないこと。
7. キャッシュがある状態で次の取得を失敗させる。ダウンロードが発生せず、旧キャッシュを最新として扱わないこと。
8. 取得中のlogout/login、未確定の保存がある場合に出力を中止すること。未ログイン時はDB出力ボタンを出さないこと。
9. 旧LocalStorageキーと他ツールのデータが不変であること。DB更新コマンド/旧保存APIが呼ばれないこと。
10. メモ/期限帳のDB版からリンクで移動できること。従来の端末バックアップ欄とDB出力欄の区別が明確であること。

実端末での保存ファイル確認・本番認証・復元演習は工程5で実施する。ファイル検証だけで復元成功としない。

関連: [仕様](../specs/tools/data-transfer.md)、[判断記録](../decision-log/2026-09-10-yutai-db-export.md)。

## 復元UI（合成データ／隔離DB限定）

両方のTRANSFER/RESTORE DB_PREVIEWフラグをtrueとする。本番フラグと本番DBは変更しない。
自動試験: `npx playwright test --config=playwright.yutai.config.ts yutai-restore.spec.ts`。
単体: `npm test -- lib/yutai`。画面試験のRPCは模擬応答であり、本番DB適用の証拠にはしない。

1. 専用JSONと理由を入力して差分確認。業務データが未適用であり、8種類の追加・変更・削除と全fieldを確認できること。
2. 変更前JSONをダウンロードし、再読込・checksumとbeforeの全fieldを照合。ファイル名にプランIDがあり、実端末の保存先を確認できること。
3. ダウンロード前、同意前、確認ダイアログ取消、新規プラン期限切れではapplyが送られないこと。
4. 明示確認後にapplyを1回だけ送り、全cache無効化後のworkspace全件照合で一致を確認して完了表示すること。
5. apply確定後の応答だけを切断し、結果不明表示と通常保存停止を確認。GETで同一プランの記録を取得し、追加applyなしで再取得・照合を完了すること。
6. GETがpreparedなら新プランへ移れず、同じプランのみ明示再送できること。再送はバックアップと同意を取り直すこと。
7. 期限切れ、別端末更新の40001、API無効、応答不正、再取得失敗を確認。失敗を全件一致と表示しないこと。
8. 成功receipt後に別更新相当の差分がある場合は「復元済み・差分あり」とし、勝手に再適用しないこと。
9. ページ再読込後、ファイル名のプランIDでGETして結果を確認できること。旧本人の状態はlogout/login時に消えること。
10. 確認中の日常保存は送信されず、画面移動は警告されるがバックアップのダウンロードは妨げないこと。
11. 他ツールと旧LocalStorageが不変であること。フラグ無効時に復元欄と復元通信がないこと。
12. 隔離DBの往復演習では変更前JSONを新規プレビューし、差分・バックアップ・同意を経て戻す。旧backupの自動適用はしない。

停止・リリース前確認: フラグは既定無効、service-role非使用、他owner/他テーブル非対象、backup削除なし。
進行中の結果不明要求があるままフラグ無効化を「取消成功」と扱わない。
DB内部の原子性・制約・競合・往復復旧はstock-notesの隔離SQL試験で確認する。
実スマホ/PC/ChatGPT UATと本番切替は全体工程5/6で別途行う。
