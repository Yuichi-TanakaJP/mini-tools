# 株主優待期限帳 UAT チェックリスト

## DB隔離検証（工程4）

- [ ] 円換算集計は検索0件でも全件基準。未アーカイブの正残高のみ、枚数×額面／金額残高を使用。額面NULLは換算不可件数、0円は既知額として区別する
- [ ] 期限当日・期限未設定は未使用に含み、翌日に期限切れへ移る。今月期限には当月の期限切れ残高も含む

`NEXT_PUBLIC_YUTAI_EXPIRY_DB_PREVIEW=true` の検証環境だけに適用。
[現在仕様](../specs/tools/yutai-expiry.md) / [判断理由](../decision-log/2026-09-10-yutai-rewards-db.md)。
`npx playwright test --config=playwright.yutai.config.ts` は合成認証/RPCを使用し、本番DBを変更しない。
フラグ未設定時は下記の従来UATを継続する。

- [ ] 本人の優待/全利用履歴を取得し、アーカイブ/使用済み/期限月/検索で絞り込める
- [ ] 新規作成の初期値は明示入力必須。額面なしを0にしない
- [ ] 期限・メモだけの編集で残高/初期値/紐付けを変更しない
- [ ] 10枚から2枚消費して8枚、3枚補充して11枚。初期値は10のまま
- [ ] 過剰消費・小数枚数・金額3桁小数・空欄を拒否する
- [ ] 消費応答を失って再確認しても同じ要求IDで再送され、二重減算しない
- [ ] 他端末更新と競合したら停止し、最新値を確認後にフォームを開き直す
- [ ] 編集中の再取得で入力を勝手に置換せず、明示的に開き直すと最新revisionと最新入力値を組にする
- [ ] 金額123.45円から0.29円を消費すると、123.16円になる
- [ ] 理由と確認付きの残高訂正・履歴取消で対象残高だけ再計算される
- [ ] アーカイブ中の残高操作を止め、解除後も元の残高/履歴を保持する
- [ ] 単位変更は新残高を明示し、旧履歴を監査へ残すと確認してから実行する
- [ ] 優待削除は理由必須。確認取消では送信しない。確認後も他の優待/履歴は残る
- [ ] 旧v2/legacyキーに書き戻さず、旧同期送信を起動しない
- [ ] 未ログイン時は本人データ・追加ボタンを表示しない
- [ ] 今月/来月以降/期限切れ/期限未設定で絞り込め、12月末から翌1月の切替と期限当日の境界が正しい
- [ ] 期間件数は検索に関係なく全件中の未アーカイブ・残高あり。使用済み/アーカイブ表示を切り替えても件数の基準は変わらない
- [ ] 明示期限月と期間ボタンは相互リセット。検索0件の案内、期限なしを最後にする順序、企業名順、登録順が正しい
- [ ] カード/表で同じ残高・初期値・額面・全履歴を表示し、表の詳細から保存できる。NULLと0、小数、管理単位を保持
- [ ] DB版カードの通常状態では「使う」「優待を編集」だけが常時表示され、「その他の操作」を開くと補充・残高訂正・管理単位変更・アーカイブ・削除を実行できる
- [ ] 表示切替や検索だけのDB/旧同期writeは0。入力中の編集を勝手に保存しない
- [ ] 幅390pxでページ全体が横にはみ出さず、表だけ横スクロールできる。画面復帰時に基準日と期間件数を更新する

単体テスト: `npm test -- lib/yutai`。実DB・実端末の往復や監査からの復旧は工程5で実施する。

## データ取得の仕組み（確認の前提知識）

- **完全 Client-side のツール**。データは端末の LocalStorage のみに保存される
- サーバー・API との通信なし
- SSR では空（LocalStorage 非参照）、クライアント hydration 後にデータが表示される

## 正常系チェックポイント

### 初回利用（データなし）

- [ ] ページが正常表示される
- [ ] 「登録なし」などの空状態が表示される

### データ追加・編集

- [ ] 優待期限を追加できる（優待名・銘柄・期限日・メモなど）
- [ ] 追加後に一覧に表示される
- [ ] 編集ダイアログが開き、内容を変更できる
- [ ] 削除できる

### 表示フィルタ

- [ ] 初期表示は「今月の未使用」に絞り込まれる
- [ ] 「完了済みを表示」トグルで完了済みも表示できる

### アーカイブ

- [ ] カード / リストの「アーカイブ」操作で、その優待を一覧から退避できる
- [ ] アーカイブ済みは既定で一覧・件数・金額集計から除外される
- [ ] 「アーカイブを含む」トグルを ON にするとアーカイブ済みも一覧に表示される
- [ ] アーカイブ済みアイテムには「アーカイブ済」バッジが付き、淡色表示になる
- [ ] 「アーカイブ解除」で元の一覧に戻せる
- [ ] アーカイブ / 解除の直後に Undo トーストが出て、取り消せる

### レイアウト切り替え

- [ ] カード表示 / テーブル表示の切り替えが動作する
- [ ] デスクトップとモバイルで適切なレイアウトが表示される

### データ永続性

- [ ] ページをリロードしても登録内容が保持される（LocalStorage に保存されている）
- [ ] 別タブで同じページを開いても同じデータが表示される

### ホーム通知

- [ ] 今日が期限の未使用アイテムが、ホームで「本日期限」と表示される
- [ ] 期限まで1日から7日の未使用アイテムが、ホームで「あとN日」と表示される
- [ ] 期限まで8日以上、期限切れ、期限なしのアイテムはホーム通知に表示されない
- [ ] 使用済みまたはアーカイブ済みのアイテムはホーム通知に表示されない
- [ ] 通知は期限が近い順で、一覧は最大3件のプレビューになる
- [ ] 「優待期限帳で確認する」から `/tools/yutai-expiry` へ移動できる
- [ ] LocalStorage の登録内容が通知確認のためにサーバーへ送信されない

## 異常系チェックポイント

| シナリオ | 期待する挙動 |
|---|---|
| LocalStorage が無効（シークレットモードなど） | エラーメッセージ、または空状態で表示（ページクラッシュなし） |
| SSR 時（JS 未実行） | 空状態が表示（hydration 後にデータが反映） |

## DBスキャンと累計

- [ ] premium未ログインではスキャンを出さず、ログイン後のみ撮影/画像選択が可能。読取結果だけでは保存しない
- [ ] 読取名・枚数・期限・額面を修正して確認保存。取消ではDB書込み0。既存への補充は期限/額面一致を必須とする
- [ ] 集計API失敗を0円にせず、単位変更前の利用と新単位の初期値を二重計上しない。不明初期値/分類/額面と未確定の累計失効を表示する
- [ ] 再取得・logoutで古い集計結果を表示しない

## DBプレビューのホーム通知


- [ ] 期限帳DBフラグ有効時、ホームもDB残高を参照し、当日/7日後は対象、8日後・期限切れ・使用済み・アーカイブは対象外になる
- [ ] 取得成功後に通信を失敗させると古い銘柄が消え、未確認と表示される。再取得成功の0件とは区別される
- [ ] ログアウト後は本人の期限情報が消える。旧LocalStorageは変更されず、代わりに表示されない
- [ ] 復帰時の日付変更が反映され、市場通知は従来のまま表示される
