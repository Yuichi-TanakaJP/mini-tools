# パスワードのリセット・変更 UAT

## 前提

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` が設定されている。
- Supabase プロジェクト側の `site_url` / `redirect URLs (uri_allow_list)` に、確認環境のオリジン（例: `https://<preview-domain>` や本番ドメイン）と `/account/reset-password` への遷移が許可されている。
- テスト用アカウント（メールアドレス・現在のパスワードが分かっているもの）が1つ用意されている。

## 確認項目

### 正常系: リセット申請 → メール → 新パスワード設定 → ログイン

- 未ログイン状態で `/account` を開き、「パスワードを忘れた場合」を押すとメールアドレス入力欄が表示される。
- テスト用アカウントのメールアドレスを入力して送信すると、「メールを送信しました。届いたリンクから新しいパスワードを設定してください。」と表示される。
- 受信したメールのリンクを開くと `/account/reset-password` に遷移し、「確認中…」の後に新しいパスワード入力フォームが表示される。
- 8文字以上のパスワードを入力し、確認用にも同じ値を入力して「パスワードを変更」を押すと、「パスワードを変更しました。」と表示され、`/account` への導線が表示される。
- `/account` に戻り、新しいパスワードでログインできる。
- ページ表示直後の URL（アドレスバー）から `code` / `token_hash` / `access_token` 等のトークンが消えている（`history.replaceState` 済み）。

### 異常系: 期限切れリンク

- リセットメールのリンクを1時間以上経過してから開く（または既に一度使用済みのリンクをもう一度開く）。
- 「リンクの有効期限が切れています。もう一度リセットを申請してください。」と表示され、`/account` でリセットを申請し直す導線が表示される。
- 新しいパスワード入力フォームは表示されない。

### 異常系: 直接アクセス（トークン無し）

- `/account/reset-password` にトークン無しで直接アクセスする。
- 「このページはリセットメールのリンクから開いてください。」と表示され、`/account` へ戻る導線が表示される。
- 新しいパスワード入力フォームは表示されない。

### アカウント列挙防止

- `/account` の「パスワードを忘れた場合」に、mini-tools に**登録されていない**メールアドレスを入力して送信する。
- 登録済みメールアドレスを送信したときと**同じ文言**（「メールを送信しました。…」）が表示され、存在有無の違いが画面に出ない。

### ログイン中の変更

- テスト用アカウントでログインした状態で `/account` を開くと「パスワードを変更」セクションが表示される。
- 新しいパスワード・確認用パスワードを入力して「パスワードを変更」を押すと「パスワードを変更しました。」と表示される。
- 一度ログアウトし、変更後のパスワードで再ログインできる。

### 入力バリデーション

- パスワード入力を7文字以下にして送信すると「パスワードは8文字以上で入力してください。」と表示され、送信されない。
- 新しいパスワードと確認用パスワードが一致しない状態で送信すると「確認用パスワードが一致しません。」と表示され、送信されない。

### スマホ表示

- 幅375px相当（iPhone SE 相当）で `/account` の各セクション（ログイン/新規登録、パスワードを忘れた場合、パスワードを変更、同期）と `/account/reset-password` が横スクロールなく表示される。
