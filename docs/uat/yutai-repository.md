# 優待共通データ層 UAT / 接続時の受入確認

対象: [共通データ層仕様](../specs/cross-cutting/yutai-repository.md)。
工程3は画面未接続のため自動契約テストで共通処理を検証し、画面/実sessionの操作確認は工程4〜5で行う。
実施結果はPR本文に記録する。この手順書をチェック済み証跡として扱わない。

## 工程3 自動検証

### 保存状態のコンパクト表示

PCおよび幅375pxの画面で確認する。
通常時はクラウド保存・更新・詳細だけの小さな行になり、詳細を開くと保存先と取得日時が読める。
キーボードでも更新・詳細に到達でき、横スクロールを生まない。
読み込み中や未ログインを保存済みとして表示しない。
通信失敗、古いデータ、復元中、保存結果不明の注意と再確認操作は、詳細を開かず読める。

環境: 専用worktree、lockfileの既存依存、合成データのみ。

1. `npm test -- lib/yutai`。正常、異常、境界と本人切替が全て成功すること。
2. 同じ月の並行loadは1通信、30秒以内の通常loadは再利用、強制loadは再取得。
3. 月間cacheは分離。NULLと0の仕込み目安、手入力株数と優待価値、booleanを変更しない。
4. 通信断は元の表示と最終取得時刻を残し、stale/errorを返す。offline保存は送信しない。
5. 要求の二重クリックは1通信。不明結果の再試行は同一ID・日時・payload。
6. 競合は読み直すだけで上書きしない。DB成功後の読込失敗はsaved_refresh_failed。
7. logout/別本人/同一本人への再loginでは古いdataとprepared要求を使えない。
8. 旧本人の遅いread/write/session応答を新本人へ公開しない。
9. Auth callback内でRPCを開始せず、確認したsessionのtokenを要求へ固定する。
10. `npm test`、`npm run lint`、`npm run build`。既存画面のimport/保存先に差分がないことをdiffで確認。

## 工程4〜5 実画面・実session確認（未接続の今は実施不可）

環境: Previewまたはローカル、専用試験アカウント/合成データ。個人データで破壊的テストをしない。

1. 実ログインで月8/9のメモ・全年度仕込み・archive含む残高履歴を読み、DBとの一致を確認。
2. 株数100、優待価値5000、仕込み目安0を保存し、再ロード・別端末で一致を確認。
3. ChatGPTから更新後、MiniToolsへ復帰/手動更新して表示が変わることを確認。
4. 保存中に通信を切断。不明結果を成功や失敗と断定せず、同一要求再確認で二重記録しないこと。
5. 保存応答の後だけreadを失敗させ、「保存済み・再取得失敗」の表示とread-only再試行を確認。
6. 編集途中に他端末から同じ行を更新。競合を表示し、利用者の再確認なしに上書きしないこと。
7. logout直後・別アカウントlogin後、以前のメモ/残高が一瞬でも表示されないこと。
8. offlineで保存操作を無効にし、取得済み表示に最終取得時刻を出すこと。
9. 不明結果があるフォームからの離脱を警告し、再確認なしに新規要求を作らないこと。
10. 全24操作を既存UI操作へ対応付け、暗黙LocalStorage書き戻し・旧同期の迂回経路も検査。

## 単一フラグでの切替確認

1. 個別previewフラグを設定せず `NEXT_PUBLIC_YUTAI_DB_CANONICAL=true` だけで起動する。
2. メモ・候補・ダッシュボード・期限帳・ホーム通知・データ移行がDB版になる。
3. 旧優待7キーを含む同期POSTは409で拒否し、tool_dataに変更がない。他ツールだけの同期は維持する。
4. 端末バックアップのmerge/replaceで旧優待キーが上書き・削除されず、他ツールは従来どおり取り込まれる。
5. 旧サーバーが優待データを返しても、新クライアントはLocalStorageへ反映しない。
6. フラグ未設定では旧動作を維持。切替後のDB更新があれば、無条件に旧版へ戻さず最新DBを保全する。

## 復旧境界

工程3だけなら追加コードのrevertで復旧でき、DB/LocalStorage復元は不要。
画面接続後の復旧では新DBの最新更新をexport・退避・照合してから操作する。
旧スマホbackupで上書きして最近の更新を失わせない。詳細な実機export/復旧試験は工程5。
